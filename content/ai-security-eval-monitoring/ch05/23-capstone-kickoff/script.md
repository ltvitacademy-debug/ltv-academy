# Script — Capstone Kickoff

## Segment 1 (title)

This course has built two things in parallel: the discipline to evaluate an AI system before shipping, and the discipline to watch, document, and respond to it once it's live. The capstone asks you to put both halves together, end to end, for one real feature you choose.

## Segment 2 (steps: pick a feature)

The feature can be simple — a support-ticket triage assistant, a summarizer, a small RAG Q&A tool, a classifier. What matters is real inputs and outputs you can actually run calls against, not a hypothetical.

## Segment 3 (code: four deliverables)

An eval dataset of fifteen to twenty test cases. A monitoring setup with logging and at least one dashboard view. One incident response plan for a realistic failure mode. A model card documenting the system you actually built.

## Segment 4 (steps: scoping to finish)

The most common way a capstone goes wrong isn't doing the work badly — it's picking something too ambitious to finish. A five-question eval set you actually build beats a fifty-question one you plan and never complete.

## Segment 5 (outro)

Every deliverable pulls from a specific earlier lesson on purpose — this isn't new material, it's assembly. Next up: actually building the pipeline, deliverable by deliverable.
