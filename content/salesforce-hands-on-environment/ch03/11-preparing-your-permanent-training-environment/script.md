# Script — Preparing Your Permanent Training Environment

## Segment 1 (title)

Chapter Three closes out this course with something practical: turning your Trailhead Playground into a genuinely permanent training environment, instead of something you recreate for every new course.

## Segment 2 (steps: pick one and commit)

First decision: pick one org and commit to it. Reuse the playground you created back in Lesson 3 unless you have a real reason not to — fragmenting your work across five different playgrounds costs you far more than a slightly messy single org does. Give it a name you'll actually recognize, like "LTV Training Org." And log in every few weeks; playgrounds can go stale with long stretches of inactivity, so a standing calendar reminder genuinely helps.

## Segment 3 (screenshot: Rename)

If you do want to rename it properly, head back to Hands-On Orgs and click Rename. That updates the label you see — it doesn't touch the org's actual underlying username, so it's completely safe to do any time, even well after you've been using it.

## Segment 4 (screenshot: Install a Package)

Worth knowing about: Trailhead Playgrounds include an Install a Package tool, where you paste in a package ID directly. That's genuinely useful for keeping one permanent org stocked with the apps and tools you'll return to across multiple courses in this path.

## Segment 5 (screenshot: install destination choice)

And one more real decision point you'll run into: package installs ask where to install. Your permanent playground acts as the "production" choice here — there's no separate sandbox tier underneath a personal training org, since it's not tied to any company's real production org.

## Segment 6 (outro)

Your permanent environment is set. Next: keeping it from turning into chaos as it fills up — naming conventions and notes.
