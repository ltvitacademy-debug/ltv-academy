# Summarizing Content with AI Builder and Azure AI

A dispatcher at Castlebridge Logistics doesn't need to read a six-paragraph customer complaint email in full before deciding what to do with it — a two-sentence summary usually tells them everything they need. Lessons 8 and 9 pulled fixed fields and category labels out of content. This lesson is about generating new text from content: a summary, written by a generative AI model, inside a flow.

## What you'll learn

- What a **prompt** is in AI Builder, and how it differs from a fixed-category classifier
- How to use the **Run a prompt** action inside a flow, with real content as input
- How Azure AI's language service relates to what AI Builder prompts do under the hood
- How to use a prompt's generated text in a downstream action

## Prompts: generating text instead of picking a label

AI Builder's **prompt** capability lets you write instructions in plain language — "Summarize this email in two sentences, focused on what action is needed" — and run real input text through those instructions using a generative model. Unlike classification, the output isn't restricted to a category you predefined; it's new, generated text shaped by your instructions. AI Builder prompts run on GPT model versions powered by Azure OpenAI Service, which is itself part of the broader Azure AI family alongside services like Azure AI Language (which also offers summarization directly, as a standalone Azure service, for scenarios outside Power Platform entirely).

You build a prompt once, in AI Builder's prompt builder, giving it a name and an **input** (for Castlebridge, an input named `EmailBody`, of type text). You write the instruction referencing that input, test it with sample text, and save it.

## Running a prompt inside a flow

Once a prompt exists, you call it with the **Run a prompt** action (this action was previously named **Create text with GPT using a prompt**, before May 2025). Add it after a trigger that gives you the content to summarize — for Castlebridge, a flow triggered by **When a new email arrives** in the support inbox. Select your summarization prompt from the dropdown, and the input fields you defined appear below it, ready to be filled with dynamic content from the trigger.

![A 'Run a prompt' action with a prompt selected and its input field filled with dynamic content from an earlier step.](/courses/power-automate-ai-agents/ch02/10-summarizing-content-with-azure-ai/prompt-input-dynamic-content.png)
*The prompt's input — EmailBody, for Castlebridge — gets filled exactly like any other dynamic content field: from the trigger, or from an earlier action's output.*

## Using the generated summary

The **Run a prompt** action produces an output variable — typically named **Text** — containing whatever the model generated. That variable is dynamic content for everything after it, the same as a field extracted in Lesson 8 or a category label in Lesson 9.

![A 'Post message in a chat or channel' action using the Text variable generated by the prompt as its message body.](/courses/power-automate-ai-agents/ch02/10-summarizing-content-with-azure-ai/use-prompt-output-in-teams.png)
*Castlebridge's dispatcher gets a Teams message with a two-sentence summary instead of the full six-paragraph email.*

For Castlebridge, that summary could post straight to a Teams channel the dispatch team watches, get appended to a tracking spreadsheet row, or feed into the next action in a longer flow. Because the output is just text, it slots into any action that accepts a text input — nothing about downstream steps needs to know AI generated it.

## Key terms

- **Prompt** — a reusable, plain-language instruction run against input text or a document by a generative AI model
- **Run a prompt** — the flow action that executes a prompt (named Create text with GPT using a prompt before May 2025)
- **Azure OpenAI Service** — the Azure AI service that powers AI Builder prompts underneath
- **Azure AI Language** — a separate Azure AI service offering summarization directly, outside Power Platform
