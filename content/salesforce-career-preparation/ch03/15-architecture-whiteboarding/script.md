# Lesson 15 — Architecture Whiteboarding · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

## S1 · TITLE

Whiteboard rounds test communication as much as technical knowledge. This lesson covers the mechanics and a repeatable structure for running one well.

## S2 · STEPS — A communication test in a technical costume

You can have the right design in your head and still lose the room if you draw in silence, write illegibly, or turn your back on the panel. The whiteboard itself is being graded, right alongside the architecture.

## S3 · STEPS — The mechanics

Start high-level, then zoom in. Label everything so it's readable without explanation. Show data flow with arrows and call out integration points explicitly. Mark security boundaries where data crosses from internal to external. And explain as you draw, not after -- silence reads as uncertainty.

## S4 · STEPS — A repeatable structure

Clarify the requirement out loud first. Sketch objects and relationships. Add the security model as boundaries around them. Add integration touchpoints, showing direction. Add automation, noting sync or async. Then talk through what happens at real scale.

## S5 · STEPS — A worked example (fictional)

This scenario is entirely fictional, for practice only. "Fairmont Logistics" needs shipment tracking with external status updates and driver-specific visibility. Clarify first whether "status updates" means real-time or batch, since that single answer changes the integration pattern. Then build up: objects, security model, integration touchpoint, automation, and scale.
