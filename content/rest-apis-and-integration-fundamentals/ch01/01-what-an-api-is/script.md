## S1 · TITLE CARD

An API — Application Programming Interface — is a defined way for one piece of software to ask another for data or to make it do something, without a person clicking through a screen. Every letter in the name describes a piece of it.

## S2 · STEPS CARD

Application is the software that actually holds the data or does the work — Oracle Fusion Financials, in this course. Programming is the defined, documented way code talks to it. Interface is the literal door: a specific set of requests the application has agreed to answer.

## S3 · CODE CARD

Here's the same result reached two ways. By hand, you'd log into Oracle Fusion, open Payables, search for an invoice, and read the amount off the screen. By API, a program sends one request to a URL and gets the same invoice data back as structured JSON — no screen involved at all.

## S4 · STEPS CARD

For a Financials consultant, this matters in three everyday situations: an outside system creating invoices or journal entries automatically instead of someone keying them in; a reporting tool pulling balances on a schedule without anyone running a manual export; and numbers that only ever get entered once, because nothing has to be re-typed from one system into another.

## S5 · OUTRO CARD

That's the core idea — an API is just a second, program-friendly door into an application you already know. Next lesson, we look at REST, which is the specific style of API that Oracle Fusion — and most modern cloud software — actually speaks.
