# Lesson 5 — Reading API Documentation · Voiceover script

Segments map 1:1 to slides. Target: ~2.75 minutes total.

---

## S1 · TITLE CARD

Opened cold, API documentation can look overwhelming. Every good doc
page answers the same three questions, though — find those first, and
the rest is just detail.

## S2 · SCREENSHOT (swagger petstore endpoint list)

This is a real, live documentation page, generated by Swagger UI — a
tool that builds docs straight from an API's own specification. Look at
the color coding: green for POST, orange for PUT, blue for GET. That
convention shows up across most documentation tools, not just this one.

## S3 · STEPS CARD (three things to find first)

So here's what to look for, in order. Base URL and auth — where do
requests go, and how do you prove who you are. Endpoints — what
resources exist, and which methods work on each one. Required
parameters — what you must send, versus what's optional.

## S4 · SCREENSHOT (swagger petstore required param)

Click into an endpoint and it spells everything out. Here, the status
parameter is marked required, typed as an array of strings, sent as a
query parameter, limited to three allowed values. Miss a required
parameter, and that's one of the most common ways to earn yourself a 400
Bad Request.

## S5 · SCREENSHOT (type-def docs)

Here's a completely different documentation site, built by a different
tool — and it answers the exact same questions: required headers, each
parameter's type, the valid values. Once you know what to look for, you
can read almost any API's docs.

## S6 · CODE CARD (doc to real request)

And that's the whole translation. Take the documented method, the URL,
the required parameters — and you've got the real request Lesson 4
already taught you the anatomy of.

## S7 · OUTRO CARD

Base URL, endpoints, required parameters — that's how you read any
API's docs. Chapter one is done. Next up, chapter two: the JSON that
fills every one of those request and response bodies.
