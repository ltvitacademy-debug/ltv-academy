# Script — SQL Server On-Prem vs. Azure SQL — Understanding the Ecosystem

## Segment 1 (title)

On-prem SQL Server means you own the whole stack — hardware, OS patching, SQL Server patching, storage, backups, HA/DR, all of it. Azure SQL is Microsoft's umbrella term for a family of options that each move a different slice of that ownership onto Microsoft instead.

## Segment 2 (code: on-prem ownership list)

On a traditional on-prem server, you or your infrastructure team own everything above the concrete floor — hardware, the operating system, SQL Server itself, networking, backups, and the pager at 2 a.m. when any layer fails. Total ownership, total responsibility.

## Segment 3 (code: the real shift is ownership, not location)

The real shift isn't "the same server, somewhere else" — it's which responsibilities move to Microsoft and which stay with you, and that split is different for each of the three deployment options. Patching an OS you'll never touch isn't automated away, it just stops being your job.

## Segment 4 (outro)

Understanding that there's a trade, and what's being traded, is what makes the next lesson's comparison make sense. Next up: the three concrete options this umbrella actually covers, side by side.
