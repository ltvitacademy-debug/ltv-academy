# Script — Screen Flows

## Segment 1 (title)

Lessons 6 and 7 covered flows that run with no one watching. A screen flow is the opposite: built to put a screen in front of a user, collecting or displaying information as they go.

## Segment 2 (screenshot: screen flow toolbox and canvas)

The canvas looks like any other flow, but with Screen elements doing the interaction work — here, a Questions screen sits right after Start, before the flow creates a Case.

## Segment 3 (screenshot: Screen Properties)

Each Screen element starts with its own Screen Properties: a label, an API name, navigation options.

## Segment 4 (screenshot: Display Text component)

Then you fill the screen with components — the actual pieces a user sees. Display Text is one of the simplest: pure output, no input required.

## Segment 5 (screenshot: component configuration)

Drag any component onto the canvas and its own configuration panel opens — label, the resource it reads or writes, visibility conditions. Text fields, picklists, toggles all work the same way.

Next up: scheduled flows — automation that runs on a clock instead of a trigger or a screen.
