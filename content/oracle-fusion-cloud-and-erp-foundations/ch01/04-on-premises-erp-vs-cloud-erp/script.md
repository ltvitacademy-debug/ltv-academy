# Script — On-Premises ERP vs. Cloud ERP

## Segment 1 (title)

Every ERP has to run somewhere. For decades that meant the company's own data center. Today it usually means the vendor's cloud. This distinction matters because Oracle, the vendor this entire path is built around, sells both.

## Segment 2 (steps: on-premises)

With on-premises ERP, the company buys the software and runs it on its own hardware. Its own IT department installs it, patches it, backs it up, and plans upgrades — often multi-month projects, on the company's own schedule. Deep control, but all of that control is also all of that responsibility.

## Segment 3 (steps: cloud / SaaS)

With cloud ERP, the vendor owns the servers, the database, and the application itself, and the customer just accesses it through a browser for a subscription fee. New features arrive continuously, on the vendor's schedule, with nothing for the customer to install.

## Segment 4 (code: the real trade-off)

Neither model is simply better. A company with deeply specialized processes and a large IT team might prefer on-premises control. A company that wants to run its business, not a data center, leans toward cloud.

## Segment 5 (outro)
