# Script — The SaaS Model and What Oracle Manages for You

## Segment 1 (title)

Lesson 4 introduced SaaS in general. Now let's make it specific to Oracle: what does Oracle actually manage for you in Fusion Cloud, what's left to the customer, and how does that shape the functional consultant job?

## Segment 2 (code: multi-tenant SaaS)

Fusion Cloud runs multi-tenant: many customers share Oracle-managed infrastructure, with their data securely isolated from each other. One codebase, one set of infrastructure, serving everyone — that's what makes the SaaS economics work.

## Segment 3 (steps: who manages what)

Oracle manages the data center, the operating system, the database, the application itself, and every update. The customer manages setup and configuration choices, security roles, the actual business data, and training its own people.

## Segment 4 (steps: configuration, not customization)

In an on-premises product, a dev team can rewrite the underlying code. In multi-tenant SaaS that's structurally impossible — so Fusion Cloud is changed through configuration, setup screens, not code. Real extension happens through sanctioned tools that sit alongside the core app: OTBI for reporting, Visual Builder for extensions, REST APIs for integration.

## Segment 5 (outro)

Nearly everything a functional consultant does lives in the customer's column — setup, security, approval rules — never the server patching Oracle already handled. Next up, Lesson 8: how this compares directly to Oracle's older on-premises product, E-Business Suite.
