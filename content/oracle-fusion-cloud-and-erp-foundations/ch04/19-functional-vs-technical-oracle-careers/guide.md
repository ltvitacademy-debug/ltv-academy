# Functional vs. Technical Oracle Careers

**Chapter 4 · Implementation Basics and Careers · Lesson 19 of 20**

Lesson 17 mentioned functional and technical consultants in passing. This lesson gives the distinction its own space, because it's one of the first real career decisions you'll face on this path, even if you can — and many people do — move between the two over a career.

## What you'll learn

- What a functional consultant actually does, day to day
- What a technical consultant actually does, day to day
- Where the line between them blurs, and why it's blurring further
- Which side this career path, and this specific course sequence, prepares you for

## The functional consultant

A **functional consultant** understands business processes deeply and configures Oracle Fusion Cloud to support them, almost entirely through Setup and Maintenance (Lesson 18) rather than code. Day to day, this looks like: running fit-gap sessions with stakeholders, deciding how the Chart of Accounts should be structured, configuring approval rules for invoices, building and running OTBI reports, leading CRPs and UAT, and troubleshooting "why doesn't this invoice post" style issues by tracing through configuration and process, not code. This role leans on accounting and business-process knowledge as much as on Oracle product knowledge — which is exactly why this career path spends Chapter 1 and the next course, Accounting Fundamentals for Oracle Professionals, building that foundation before going deep on Oracle itself.

## The technical consultant

A **technical consultant** works on the pieces that sit outside pure configuration: data loads using **FBDI** (File-Based Data Import) and **HDL** (HCM Data Loader) for mass-loading data, building integrations using **REST APIs** and Oracle Integration Cloud, writing more advanced reports in **BI Publisher**, building small extensions in **Visual Builder**, and occasionally **Groovy** scripting for specific business rules. This role leans more on programming, data, and integration skills — a different, though related, skill set from the functional side.

## Where the line blurs

In practice, these roles aren't perfectly separate. Many functional consultants pick up enough FBDI and REST API knowledge to be dangerous with data loads. Many technical consultants develop enough business-process understanding to make good design suggestions, not just implement someone else's spec. As Oracle leans further into low-code extension tools, the gap between "pure functional" and "pure technical" has narrowed compared to the EBS era, when the split was often more rigid.

## Which side this path prepares you for

This career path's title — **Oracle Fusion Financials Consultant** — and its emphasis on accounting, business processes, and Financials configuration throughout Chapters 1 through this point, point clearly toward the **functional** side. Later courses in this path (FBDI and ADFdi, REST APIs and Integration Fundamentals) do introduce technical concepts, but as working knowledge a strong functional consultant needs, not as a technical-consultant career track in its own right.

## Key terms

| Term | Meaning |
|---|---|
| Functional consultant | Configures the system and process; works mainly in Setup and Maintenance |
| Technical consultant | Handles data loads, integrations, extensions, and advanced reports |
| FBDI / HDL | File-based tools for mass-loading data into Oracle Fusion |
| Groovy / Visual Builder | Oracle's scripting and low-code extension tools |
