# Script — Ad Hoc Analysis with Smart View

## Segment 1 (title)

With Smart View connected, let's cover what you actually do with it: pulling GL balances into a worksheet, pivoting, drilling, and refreshing, the core workflow a controller uses constantly during close.

## Segment 2 (steps)

A user connects a worksheet to a data source, commonly the same GL balances cube Financial Reporting Studio reports against. Instead of running a predefined report, they build their own ad hoc grid, choosing which dimensions go on rows, which on columns, and which stay fixed as a point of view for the whole worksheet.

## Segment 3 (steps)

Because the source is genuinely multidimensional, a user can pivot, drag a dimension from rows to columns, and the layout and numbers update accordingly. A worksheet with accounts down the rows and periods across columns can become cost centers down the rows and accounts across columns, with a couple of drags, same data, different view.

## Segment 4 (steps)

Smart View also supports drilling, starting from a summary balance and navigating down into the detail that makes it up, potentially to the underlying transactions, depending on access. And refreshing re-queries the source and updates the worksheet with current numbers, while keeping the layout and any formulas built around it intact.

## Segment 5 (outro)

This is exactly the "pull GL balances into Excel and build my own variance analysis" scenario from chapter one, the natural complement to Financial Reporting Studio's formal statements. Up next, lesson twenty-two: Report Packages and templates, Smart View's collaborative side.
