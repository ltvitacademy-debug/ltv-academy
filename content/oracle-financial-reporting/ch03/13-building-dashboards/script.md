# Script — Building Dashboards

## Segment 1 (title)

A single analysis answers one question well. A dashboard answers several related questions at once, laid out together so a team can check them every day in one place.

## Segment 2 (steps)

A dashboard doesn't have its own facts and dimensions. It's a layout container that arranges already-built analyses onto pages. The unpaid-invoices analysis from lesson eleven and a second analysis showing total payables by supplier can sit side by side on one dashboard, without rebuilding either one. You build analyses once, then compose them into however many dashboards different audiences need.

## Segment 3 (steps)

Dashboards are organized into pages, like tabs, so related but distinct content doesn't compete for space, and columns within a page, which you drag analyses into to control whether content sits side by side or stacked. A good page leads with a summary near the top, detail tables below.

## Segment 4 (steps)

Just like an individual analysis, a dashboard can have its own dashboard-level prompt, a single Business Unit selector at the top that filters every analysis on the page at once, instead of the viewer setting the same prompt separately on each one.

## Segment 5 (outro)

And dashboards aren't limited to the standalone catalog. Oracle Fusion can embed them directly inside a transactional work area, so a user sees a relevant snapshot right on, say, the Payables landing page.
