# BSON & the MongoDB Document Model

Lesson 5 called a document "a single record inside a collection, stored as BSON" without
explaining what BSON actually is. This lesson closes that gap. Every document you'll
insert, query, or edit for the rest of this course is stored on disk in this exact format
— understanding it isn't trivia, it's the reason MongoDB documents can hold real dates,
binary data, and precise decimals that plain JSON simply cannot represent.

## What you'll learn

- What BSON (Binary JSON) actually is, and why MongoDB uses it instead of plain JSON
- The real extra types BSON supports that JSON doesn't
- What the `_id` field is, and how MongoDB's `ObjectId` type is actually constructed

## BSON: Binary JSON, not just JSON on disk

BSON stands for **Binary JSON**. It's a binary-encoded serialization format: the same
nested, document-like shape as JSON (keys mapped to values, values that can themselves be
objects or arrays), but encoded as bytes rather than text, with an explicit type and
length prefixing every field. That encoding buys two real things a text format can't:

- **Traversal speed.** Because each field carries its length up front, MongoDB can skip
  over fields it doesn't need without parsing their full contents — something a text
  parser has to read character by character to do.
- **A richer type system.** Plain JSON has exactly six data types: string, number,
  boolean, null, array, and object. It has no native concept of a date, binary data, or a
  distinction between an integer and a floating-point number. BSON adds real, distinct
  types for all of that.

## Real BSON types beyond plain JSON

A relational DBA already thinks in terms of column types — `DATETIME`, `VARBINARY`,
`DECIMAL`, `INT` vs `BIGINT`. BSON has direct equivalents where JSON has none:

- **`Date`** — a real 64-bit timestamp (milliseconds since the Unix epoch), not a string
  you have to parse yourself.
- **`ObjectId`** — a 12-byte unique identifier type, covered in detail below.
- **`Binary data` (`BinData`)** — arbitrary binary content, such as a hash or a small
  file, stored natively rather than base64-encoded into a string.
- **`Int32` / `Int64`** — distinct 32-bit and 64-bit integer types, unlike JSON's single
  generic "number."
- **`Decimal128`** — a 128-bit decimal type for exact decimal arithmetic (no
  floating-point rounding error), the BSON equivalent of SQL Server's `DECIMAL`/`NUMERIC`.
- **`Timestamp`** — an internal BSON type used by MongoDB itself for internal replication
  bookkeeping, distinct from the user-facing `Date` type.

```
{
  "_id": ObjectId("66f1a2b3c4d5e6f7a8b9c0d1"),
  "name": "Priya Patel",
  "signupDate": ISODate("2026-01-14T00:00:00Z"),
  "accountBalance": NumberDecimal("1042.55"),
  "loginCount": NumberInt(37)
}
```

Compass and `mongosh` display these typed values with helper wrappers like `ObjectId(...)`
and `ISODate(...)` so you can see the real type at a glance — those wrappers aren't part
of the stored data, they're how the tools render BSON's actual types back to you.

## The `_id` field and `ObjectId`

Every document in every collection has an `_id` field, and MongoDB enforces that it's
unique within its collection — it functions as the collection's real primary key. If you
insert a document without one, MongoDB automatically generates an `_id` of type
`ObjectId`.

An `ObjectId` is a 12-byte value built from three parts:

- A **4-byte timestamp** — seconds since the Unix epoch, meaning an `ObjectId` encodes its
  own rough creation time.
- A **5-byte random value**, unique to the process generating the id.
- A **3-byte incrementing counter**, initialized to a random value, that increments for
  each `ObjectId` generated by that process.

That construction means `ObjectId`s are generated client-side, without a round trip to the
server to request the "next" value — genuinely different from an `IDENTITY` column, which
the SQL Server engine assigns. It also means `ObjectId`s sort roughly, though not
perfectly, in creation order, since the timestamp is the leading component. You aren't
required to use `ObjectId` for `_id` — any unique value works, including one you supply
yourself — but letting MongoDB generate it is the default and the common case.

## Key terms

| Term | Meaning |
|---|---|
| BSON | Binary JSON — MongoDB's binary storage/wire format, with a richer type system than text JSON |
| `ObjectId` | A 12-byte auto-generated identifier: 4-byte timestamp, 5-byte random value, 3-byte counter |
| `_id` field | The field every document has, enforced unique within its collection — the real primary key |
| `Decimal128` | A 128-bit exact decimal BSON type, avoiding floating-point rounding error |
