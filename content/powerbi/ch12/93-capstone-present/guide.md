## Presenting like it's a real stakeholder meeting

Open your published app (Lesson 91) and walk through it the way
you'd actually present to the VP of Sales:

1. **Start with the dashboard**, not a report page. Thirty seconds on
   the three pinned tiles — sales, margin, fulfillment — before
   anyone asks a single question.
2. **Follow one tile into its report** when someone asks "why," using
   the slicer (Lesson 90) to show the answer live rather than
   promising to "look into it and get back to them."
3. **Use the drillthrough** to show territory-level detail only if
   someone specifically asks for it — not by default. This is
   Chapter 8's "only what the audience needs" discipline, applied to
   a live presentation, not just a static layout.

## Checking against Lesson 84's scope — the real test

Pull up your written scope from Lesson 84 one final time and confirm,
requirement by requirement:

| Requirement | Where it lives now |
|---|---|
| Regional performance | Page 1 + dashboard tile |
| Product-line profitability | Page 2 + dashboard tile |
| Reseller fulfillment | Page 3 + dashboard tile |
| Trend over time | Page 3's YoY line chart |

If every row has an answer, the project is complete — not because it
has more features than you started with, but because it does exactly
what was asked, nothing more and nothing less.

## The one question that actually matters

Chapter 8, Lesson 66 ended with this test, and it's the right way to
end this entire course too: **hand the finished dashboard to someone
unfamiliar with the data, and see if they can name the single most
important number on the page in under ten seconds.** If they can,
every decision from Lesson 84's requirements through Lesson 92's
security setup did its job.
