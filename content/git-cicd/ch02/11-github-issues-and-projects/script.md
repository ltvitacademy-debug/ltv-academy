# Script — GitHub Issues & Project Boards

## Segment 1 (title)

Not every piece of work starts as a code change — a dashboard undercounting refunds, a requested new column, an investigation into a duplicate load. A GitHub issue is where that work lives before it has a diff.

## Segment 2 (screenshot: issue create form)

An issue's create form has everything up front — who it's for, what it's tagged, which project it belongs to — right above the description. It can turn into a pull request later, or never need one at all.

## Segment 3 (screenshot: issues labels button)

A repository accumulates dozens of open issues fast. Labels filter them without reading every title. A useful label set for a data team is small and specific — data-quality, new-metric, pipeline-failure — not a large taxonomy nobody remembers.

## Segment 4 (screenshot: example board)

A project board arranges issues and pull requests into columns — Backlog, In Progress, In Review, Done. Dragging a card between columns updates its status — a live view of what's actually being worked on, not a spreadsheet someone forgets to update.

## Segment 5 (steps: why this beats Slack)

Ad hoc coordination works until it doesn't, usually right around three or four people. Issues and boards fix the specific failure: work that only exists in someone's memory, and no way to see at a glance what's actually in progress.
