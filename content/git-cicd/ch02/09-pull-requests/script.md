# Script — Pull Requests

## Segment 1 (title)

A pull request is GitHub's layer on top of git merge — a proposal to merge one branch into another, opened before the merge happens, with a place attached for comments, suggested changes, and CI results.

## Segment 2 (screenshot: compare & pull request banner)

After you push a new branch, GitHub notices and offers to open a pull request for you directly — a yellow banner on the repository page with a Compare & pull request button, right after the push.

## Segment 3 (screenshot: branch dropdown)

Opening a PR means telling GitHub two branches: the one with your new commits, and the one you want them merged into, almost always main. The same branch switcher dropdown you'd use to browse a repo handles both sides of that comparison.

## Segment 4 (steps: why bother even solo)

It's tempting to think pull requests only matter with a teammate reviewing. Two reasons they're worth it solo: a PR is a checkpoint everything in CI runs against before main is touched, and a PR is a permanent, searchable record of what changed and why.
