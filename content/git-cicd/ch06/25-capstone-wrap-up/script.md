# Script — Capstone: Wrap-Up & Portfolio Presentation

## Segment 1 (title)

A repository is more convincing than a slide deck. Walk through it in order: the gitignore, a real pull request with actual review comments, the workflow file read out loud naming its trigger, job, and steps, a failed run followed by a passing one, and the deploy job.

## Segment 2 (steps: questions to be ready for)

This project should prepare you to answer real questions: what happens when you push a commit, what would happen if you accidentally committed a password, why two separate jobs for CI and deploy, and the difference between Continuous Delivery and Continuous Deployment — now answerable about a real project you built.

## Segment 3 (steps: the real point of this course)

None of this course was really about Git commands in isolation. It was about a specific anxiety in data work — shipping a change without breaking something nobody notices until a stakeholder does. Every practice here exists to catch that failure first.

## Segment 4 (steps: what transfers)

That habit transfers to any team, any tool, any stack. The YAML will look different at a real job. The instinct to ask whether a change has a test gate before it reaches production doesn't change.

## Segment 5 (outro)

This course is complete when you can walk a stranger through your capstone repository, end to end, and answer every one of those questions without hesitation.
