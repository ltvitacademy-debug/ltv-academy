# Lesson 40 — GROUP BY ROLLUP

**Chapter 4 · Grouping and Aggregating · Lesson 9 of 11**

## What you'll learn

- What `GROUP BY ROLLUP` adds on top of a normal `GROUP BY`
- Why ROLLUP's extra rows look like real data, and how to tell them apart
- The `GROUPING()` function

## The problem: a report with subtotals AND a grand total

Every `GROUP BY` you've written so far gives you one row per group — nothing
more. A real report often needs more than that: the detail rows, **plus** a
subtotal for each broader category, **plus** one grand total row at the
bottom. `ROLLUP` adds exactly those extra rows, automatically, in a single
query.

```sql
USE AdventureWorks2012;
GO

SELECT
    Color,
    Size,
    SUM(ListPrice) AS TotalListPrice,
    COUNT(*) AS ProductCount
FROM Production.Product
GROUP BY ROLLUP (Color, Size);
```

Compare this to plain `GROUP BY Color, Size` from Lesson 36. You still get
every `(Color, Size)` detail row — but `ROLLUP` adds two more kinds of rows
on top:

- One **subtotal row per Color**, with `Size` shown as `NULL` — the total
  across every size for that color.
- One **grand total row**, with both `Color` and `Size` shown as `NULL` —
  the total across everything.

## ROLLUP rolls up in the order you give it

`ROLLUP (Color, Size)` treats `Color` as the broader level and `Size` as
nested inside it, strictly because of the **order you listed them in** —
not because SQL Server knows anything about your data. It peels columns off
**right to left**: full detail, then drop `Size`, then drop `Color` too.
`ROLLUP (Size, Color)` would roll up the other way instead, subtotaling by
`Size` first. Order matters.

## The NULL problem ROLLUP creates

Here's the catch: `Production.Product` has real products where `Color` is
genuinely `NULL` in the data — it isn't just a stand-in for "all colors."
Once `ROLLUP` is also inserting its own `NULL`s to mean "this is a
subtotal," you can no longer tell the two apart by looking at the value
alone:

```sql
SELECT
    Color,
    Size,
    SUM(ListPrice) AS TotalListPrice,
    COUNT(*) AS ProductCount
FROM Production.Product
GROUP BY ROLLUP (Color, Size);
-- Which NULL rows are "no color on file," and which are ROLLUP subtotals?
```

## GROUPING() tells them apart

`GROUPING(column)` returns `1` when that column's `NULL` in the current row
was generated by `ROLLUP` or `CUBE`, and `0` when it's an ordinary group
value (including a genuine `NULL` from the data itself):

```sql
SELECT
    Color,
    Size,
    SUM(ListPrice) AS TotalListPrice,
    COUNT(*) AS ProductCount,
    GROUPING(Color) AS IsColorSubtotal,
    GROUPING(Size) AS IsSizeSubtotal
FROM Production.Product
GROUP BY ROLLUP (Color, Size);
```

Read the two `GROUPING` columns together: `0, 0` is a normal detail row;
`0, 1` is a Color subtotal (every size, one color); `1, 1` is the grand
total row. This is the standard, reliable way to tell a rollup subtotal
from a real data value — never assume a `NULL` in rolled-up output is the
data's own `NULL`.

## Key terms

| Term | Meaning |
|---|---|
| `GROUP BY ROLLUP (...)` | Adds hierarchical subtotal rows, right to left, plus one grand total row |
| `GROUPING(column)` | Returns 1 if that column's NULL came from ROLLUP/CUBE, 0 otherwise |
