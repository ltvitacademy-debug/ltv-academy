## Opening a file with `with`

```python
with open("orders.csv", "r") as f:
    header = f.readline()
    first_row = f.readline()

print(header)
print(first_row)
```

```
order_id,customer_id,customer_name,region,product,category,quantity,unit_price,order_date,status

1001,501,Dana Whitfield,West,Trail Runner GTX,Footwear,2,129.99,2026-01-03,Shipped

```

`open()` returns a file object; `"r"` means read mode. The `with`
block closes the file automatically the moment you leave it — even if
an exception happens inside. Without `with`, you'd have to remember to
call `f.close()` yourself, on every exit path, including error paths.
In a real pipeline that runs unattended, a forgotten `close()` is how
you end up with file handles leaking until the process falls over.
`readline()` pulls one line at a time, including the trailing newline
(`\n`) — that's why `print(header)` leaves a blank line after it.

## Reading the whole file: readlines() and iteration

```python
with open("orders.csv") as f:
    lines = f.readlines()

print(len(lines))
```

```
21
```

21 lines: one header row plus the 20 order rows. `readlines()` loads
every line into a list in memory, which is fine for a 21-line file but
would be a real problem for a multi-gigabyte export — you'd load the
whole thing before processing a single row. The usual fix is to
iterate the file object directly, which reads one line at a time
without holding the whole file in memory:

```python
with open("orders.csv") as f:
    next(f)  # skip the header
    for line in f:
        fields = line.strip().split(",")
        print(fields[0], fields[2])
```

```
1001 Dana Whitfield
1002 Marcus Ibeh
1003 Dana Whitfield
1004 Priya Nandan
1005 
...
```

Notice row `1005` prints an empty string where the customer name
should be — that's the real missing value in this dataset, visible
even at this raw level, before you've opened a single pandas
DataFrame.

## Why "just split on commas" breaks down

That `line.strip().split(",")` approach works here because none of
`orders.csv`'s fields contain a comma. But it's fragile: if a
`product` name were `"Tent, 2-Person"` with a comma inside it, a naive
split would cut that field into two and shift every column after it
out of alignment. Real CSV files quote fields that contain commas
(`"Tent, 2-Person"`), and a plain `.split(",")` doesn't know to respect
those quotes. That's exactly the gap Lesson 14's `csv` module exists to
close — this lesson is deliberately showing you the fragile way first
so the next lesson's module feels like the obvious upgrade it is.

## Writing and appending text files

```python
shipped_count = 0
with open("orders.csv") as f:
    next(f)
    for line in f:
        if line.strip().endswith("Shipped"):
            shipped_count += 1

with open("orders_summary.txt", "w") as f:
    f.write(f"Shipped orders: {shipped_count}\n")
    f.write("Generated by Lesson 13 script\n")
```

`"w"` mode creates the file if it doesn't exist, and **overwrites it
completely** if it does — run that script twice and the second run
replaces the first output, it doesn't add to it. `"a"` (append) adds
to the end of an existing file instead:

```python
with open("orders_summary.txt", "a") as f:
    f.write("Re-run confirmed.\n")
```

Mixing those up — using `"w"` when you meant `"a"` — is a common way to
silently destroy a log file in a real pipeline.

## Key terms

| Term | Meaning |
|---|---|
| `open(path, mode)` | Opens a file; returns a file object to read or write through |
| `with` statement | Guarantees the file closes automatically, even if an error occurs |
| `"r"` / `"w"` / `"a"` | Read / write-and-overwrite / write-and-append modes |
| `readline()` / `readlines()` | Read one line, or all lines into a list |
| Iterating a file object | Reads one line at a time without loading the whole file into memory |

## Lab

Write a script that:

1. Opens `orders.csv` and counts the total number of data rows (not
   counting the header).
2. Counts how many of those rows have an empty `customer_name` field
   (hint: split each line on `,` and check index `2`).
3. Writes both numbers to a new file, `orders_text_audit.txt`, one per
   line.

```python
total_rows = 0
missing_names = 0

with open("orders.csv") as f:
    next(f)
    for line in f:
        total_rows += 1
        fields = line.strip().split(",")
        if fields[2] == "":
            missing_names += 1

with open("orders_text_audit.txt", "w") as f:
    f.write(f"Total rows: {total_rows}\n")
    f.write(f"Missing customer names: {missing_names}\n")
```

Running it should report 20 total rows and 1 missing customer name —
the same row 1005 you saw printed above.
