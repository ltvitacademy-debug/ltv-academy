# Lesson 11 — Scheduling Scans · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

---

## S1 · TITLE CARD

The last decision before you save a scan is its trigger — run it once, or set it up to recur on its own.

## S2 · SCREENSHOT (scan trigger)

Recurring is the common choice. Set a time zone, a recurrence — daily, weekly, monthly — a start date, and optionally an end date if it shouldn't run forever.

## S3 · STEPS CARD (picking a cadence)

Daily or weekly suits sources that change often. Monthly fits ones that barely change. And always coordinate with whoever owns that source — scanning is real load on the system underneath.

## S4 · SCREENSHOT (select scans)

Once a scan exists, find it from its collection or domain's Overview tab — Assets, Sources, and Scans counts are right there.

## S5 · SCREENSHOT (select scan name)

Select Scans to open the list, then select the scan's name for its full run history and management options.

## S6 · SCREENSHOT (full or incremental)

When you re-run a scan, you choose how much it re-reads. Full Scan covers everything in scope again. Incremental only processes what's changed since the last run — and it's the default after that first scan.

## S7 · STEPS CARD (one caveat)

Not every source supports incremental scanning. Check that source's own Supported capabilities table before you assume it's there — some sources only ever run full.
