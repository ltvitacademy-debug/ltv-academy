# Script — Report Types, Overview

## Segment 1 (title)

Welcome to Salesforce Reports and Dashboards. You already know how to query Salesforce data with SOQL. This course covers the native, click-based way to analyze it, and we'll be honest about where that approach runs out of road.

## Segment 2 (steps: three ideas)

Three ideas get confused right away. A report type decides which objects and fields a report can use. A report format decides how the results are laid out. And Report Builder is the editor where you assemble both. Keep those three straight and half the confusion around Salesforce reporting disappears.

## Segment 3 (screenshot: Report Builder)

Here's the real Report Builder in Lightning Experience. On the left, an Outline tab for groups and columns, and a Filters tab. On the right, a preview of a limited number of records. Save and Run sits at the top.

## Segment 4 (screenshot: Fields pane)

The Fields pane opens from the arrow on the left edge. Everything the report type exposes lives there, including fields from related objects. That's the data model you learned, now as a menu you drag from.

## Segment 5 (steps: four formats)

Once the type is chosen, you pick a format. Tabular is a flat list. Summary groups rows and adds subtotals. Matrix groups by rows and columns. Joined places several report blocks side by side. The next four lessons take these one at a time.

## Segment 6 (outro)

Choose the report type carefully, because it's hard to change later and it caps what you can ever show. If a field you need is ever missing, check the report type first, because the Fields pane can only show what the type exposes. Next up: tabular reports.
