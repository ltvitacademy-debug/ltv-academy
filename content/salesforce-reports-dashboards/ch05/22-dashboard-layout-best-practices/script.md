# Script — Dashboard Layout Best Practices

## Segment 1 (title)

The Dashboard Builder will let you drop twenty widgets on a page. This lesson is about the editorial side: where things go so the reader gets it in seconds.

## Segment 2 (screenshot: editor layout)

Start with the audience and the question. Write one sentence: this dashboard helps someone decide something. Then lay it out the way people read. In this real dashboard, filters sit across the top. Small metric widgets are on the left. A large trend chart takes the most space, and a table sits lower down for detail.

## Segment 3 (screenshot: sales dashboard)

Here's a finished version. The pipeline funnel, top accounts, and open opportunities each answer a question, and every title says what it is, with the time frame underneath. A date filter sits above them. Every widget ends in a View Report link, so detail lives one click away rather than crammed on the page.

## Segment 4 (steps: principles)

Four principles. Headline first: your most important numbers go top left as metrics or gauges. Size signals importance, so the main story gets the biggest widget. Keep it small, roughly a half dozen to ten widgets. And stay consistent with titles, chart types, and colors, reserving red for problems.

## Segment 5 (code: layout sketch)

Sketch it before you build. Row one: filters. Row two: three or four metrics. Row three: a funnel and a trend chart. Row four: a table. If you need more than that, you probably have two dashboards.

## Segment 6 (outro)

Finally, open it as a viewer, not as the builder, and ask whether someone new could find the headline number in five seconds. If they can't, simplify. Next: how dashboards behave on mobile.
