# Script — Dashboard Components

## Segment 1 (title)

A report answers one question in detail. A dashboard puts several answers side by side. This lesson covers the building blocks: components, which the Dashboard Builder calls widgets.

## Segment 2 (screenshot: dashboard editor)

Here's the real Lightning Dashboard Builder. Up top, the plus Widget button offers a chart or table, a text box, or an image. Below, widgets sit on a grid. You drag them to move them and drag their edges to resize. Notice each one ends in a View Report link. That's the key idea: a dashboard stores no data of its own.

## Segment 3 (screenshot: add widget dialog)

Every chart or table widget is drawn from a source report. In the Add Widget dialog you pick the report, then how to display it, the value to measure, and the field to slice by. The preview updates live. You can show values, use shortened numbers, and combine small groups into Others.

## Segment 4 (steps: widget types)

Choose the display by the question. Bars compare groups. Lines show trends. A donut fits a few parts of a whole. A funnel suits pipeline stages. A metric shows one headline number, and a gauge shows progress toward a target. Lightning tables add detail, up to ten columns and two hundred rows.

## Segment 5 (code: report to widget rule)

Here's the rule to remember. The widget can only show what its report contains. No grouping in the report, no chart to slice. Change the report's filters, and every widget built on it changes too. Build focused reports first, and name them clearly.
