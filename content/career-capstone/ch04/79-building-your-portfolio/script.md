# Script — Building Your Data Engineering Portfolio

## Segment 1 (title)

A hiring manager reviewing a portfolio spends minutes, not hours, on any one project — often just the README and one diagram before deciding whether to look closer. That changes what's actually worth polishing.

## Segment 2 (steps: what the README needs to answer)

Four questions, in order: what does this system do, what does it look like, what were the hard decisions, and how do I run it. The hard-decisions section comes straight from the retrospective — the honest, specific answer to "what would you change" is exactly what a resume bullet can't convey but a README paragraph can.

## Segment 3 (steps: the architecture diagram)

A good diagram shows five or six boxes and arrows — the shape of the system, not every configuration setting. The test: could someone who never took this course understand the system from the diagram alone, in under a minute?

## Segment 4 (outro)

Three projects, three READMEs built this way, retrospectives mined for their specifics — that's a portfolio, not a list of finished coursework. Next up: turning that same material into a spoken interview story.
