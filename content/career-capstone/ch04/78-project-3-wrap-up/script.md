# Script — Project 3: Wrap-Up and Retrospective

## Segment 1 (title)

Three projects into this capstone chapter, the pattern should be obvious: every project is a composition exercise. Project 3 alone reached across all four courses in the track — Kappa architecture and idempotency from this course, Eventstreams and windowing from Fabric, MERGE INTO from Databricks, estimation from Foundations — all in three lessons.

## Segment 2 (steps: what got built)

Kickoff fixed the scenario, the latency budget, and the architecture fit before any tool was chosen. Ingestion computed rolling features on a sliding window, with a deliberate watermark trade-off. Scoring and alerting closed the loop, made idempotent with a keyed merge.

## Segment 3 (steps: the retrospective again)

Same three questions as Project 2's wrap-up, applied to a very different system. What worked, specifically. What you'd change, now that real numbers exist. What surprised you — usually how much got decided before any code was written. Writing it down matters more here, not less: real-time systems fail in ways that are harder to notice after the fact.

## Segment 4 (outro)

All three capstone projects are complete. What's left is a genuine turn — not technical lessons, but turning these three projects into a portfolio and an interview story that actually gets attention. Next up: building that portfolio.
