# Script — The Limits of AI in Data Engineering, Honestly

## Segment 1 (title)

This site's policy has been the same from the start: don't oversell what a tool can do. This chapter showed real places AI helps. It would be dishonest to end without saying, just as plainly, where it doesn't.

## Segment 2 (code: deep system context)

Every technique in this chapter worked from what you fed it — a spec, a log, a schema. It has no access to the tribal knowledge that actually runs most real systems, and no amount of prompting recovers context that was never given in the first place.

## Segment 3 (code: business-logic judgment)

Whether a returned order still counts toward this quarter's revenue is a judgment call that comes from understanding the business, not from pattern-matching text. An LLM can draft a plausible answer — it cannot know which answer is actually right for this business.

## Segment 4 (code: genuinely novel debugging)

An LLM pattern-matches an error against failures it's seen before. A genuinely novel bug has no pattern to match — and the draft in that case isn't a weak hypothesis, it's often confidently wrong.
