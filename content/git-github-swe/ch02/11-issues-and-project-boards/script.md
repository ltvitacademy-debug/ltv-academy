# Script — Issues & Project Boards

## Segment 1 (title)

A pull request proposes a specific code change. An issue is GitHub's lightweight tracker for everything that comes before that — a bug report, a feature request, a task. Every repository has an Issues tab right next to Pull requests.

## Segment 2 (screenshot: creating an issue)

A new issue is a title, a description, and optional metadata — assignee, labels, a project, a milestone. A genuinely useful issue is specific: what you expected versus what happened, and how to reproduce it. "It's broken" helps nobody, not even future-you reopening it in three weeks.

## Segment 3 (screenshot: project boards)

A single list of issues gets unwieldy fast. Projects give you a visual board — columns like Backlog, In Progress, Done — built from your issues and pull requests.

## Segment 4 (screenshot: adding an item)

Adding an item to a board view is as direct as typing in a row. It works the same whether the team is three people or three hundred — a shared, visual answer to what's actually in progress right now.

## Segment 5 (outro)

Writing Closes hash 42 in a pull request's description links it to that issue, and merging the PR automatically closes it — the connective tissue between the problem and the fix. That completes Chapter Two — Git Fundamentals and GitHub Essentials, the foundation the rest of this course builds on.
