# Script — Pull Requests

## Segment 1 (title)

A pull request is a request to merge one branch into another, usually a feature branch into main, that opens a space for discussion, automated checks, and review before the merge actually happens. Git itself doesn't need this — it's a GitHub feature built specifically as a checkpoint.

## Segment 2 (screenshot: branch dropdown)

After pushing a branch, the branch switcher on the repository's main page lets you find it directly.

## Segment 3 (screenshot: compare and pull request banner)

And once you've pushed a branch with commits ahead of main, GitHub shows a banner offering to open the comparison directly — Compare and pull request.

## Segment 4 (screenshot: PR tabs)

Every pull request has the same tabs. Conversation holds the description and every comment. Commits lists each commit individually. Checks shows automated tests running against the branch. And Files changed is the actual diff, where code review happens.

## Segment 5 (outro)

A pull request focused on one coherent change is faster to review, faster to merge, and easier to revert if something's wrong — the same discipline as a clean commit, now applied at the PR level. Next up: actually doing the review.
