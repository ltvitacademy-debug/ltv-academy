# Script — Capstone: Wrap-Up & Portfolio Presentation

## Segment 1 (title)

A real repository with real history is more convincing than a slide deck describing one. This is how to present it in an interview or portfolio review, and where this course leaves you.

## Segment 2 (steps: what to show)

Show the commit graph and a real feature branch merged through a real pull request first. Then the pull request itself — the description, and the review comment you actually addressed. Then the resolved merge conflict, explained in plain language. Then the Actions tab, with real pass and fail runs, and the deploy job's condition, explained.

## Segment 3 (steps: interview questions)

"Walk me through what happens when you merge a pull request" — answer without opening the code. "Tell me about a real merge conflict you've resolved" — point at one you actually hit. "What stops your deploy job from running on every single push?" — your own condition, in your own words.

## Segment 4 (steps: the real point)

This course was about the actual mechanics of building software on a team: proposing a change, getting it reviewed, integrating it safely, shipping it without anyone needing to remember to run the tests by hand. That instinct transfers to any team, any stack, any CI tool.
