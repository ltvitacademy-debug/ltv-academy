# Script — On-Call Basics

## Segment 1 (title)

Triage, common issues, and escalation all get tested most directly during on-call. Being effective is less about heroics and more about what's prepared before the pager goes off.

## Segment 2 (code: The runbook)

A runbook is a written, specific reference — not general knowledge, but "if X happens, check Y, and if Y shows Z, do this." It removes the need to think clearly under pressure at 2am, which is genuinely harder than thinking clearly at 2pm.

## Segment 3 (steps: What pages, and the toolkit)

Something is paging-worthy only if it's both urgent and actually actionable right now — not every anomaly should wake someone up. A pre-built folder of tested diagnostic scripts turns "paged" into "looking at the actual problem" in under a minute, instead of writing T-SQL from memory half-awake.

## Segment 4 (outro)

Whatever happens on-call eventually needs to be written down properly. Next up: incident documentation.
