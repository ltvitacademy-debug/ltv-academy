# Script — Incident Documentation

## Segment 1 (title)

Once an incident is resolved, what gets written down about it — and how — determines whether the same incident happens again in six months.

## Segment 2 (code: Blameless, and the timeline)

A blameless postmortem treats the incident as a system failure to understand, not a person to punish — blame just teaches people to hide details next time. A useful timeline is timestamped, factual events pulled from real sources, not a narrative reconstructed from memory afterward.

## Segment 3 (steps: Root cause, factors, and action items)

Most incidents have a root cause and several contributing factors — both deserve honest documentation. A real action item is specific, assigned, and changes something structural, not a vague "be more careful" that fixes nothing.
