# Script — Wrap-Up & Presentation

## Segment 1 (title)

A marketplace running on your laptop isn't a portfolio project yet -- it's a prototype. This
lesson closes that gap: the README, the talking points, and how to present this build in an
interview.

## Segment 2 (steps: what the README needs)

Four things the README needs. The problem and the three-layer architecture from Lesson 8. The
real tradeoffs you made and why. Exact commands to run it -- a reviewer who can't start it in a
few minutes often won't try twice. And your known limitations, stated plainly.

## Segment 3 (code: README skeleton)

A short skeleton: what it does, the architecture in one line, the design decisions you'll actually
be asked about, and the limitations from Lesson 8's scope list -- being upfront about scope reads
as maturity, not as a gap.

## Segment 4 (steps: interview talking points)

Three questions almost always come up. Why approval instead of escrow -- because the seller keeps
control until it sells. Why an indexer at all -- because a node can't answer "show me every active
listing." And how you handled royalties -- the real ERC-2981 standard, paid out automatically.

## Segment 5 (outro)

A smaller, fully-finished project with a clear README and ready answers beats a longer list of
half-built repos. Project 2 is done. Next: Project 3, a DAO governance system -- token-weighted
voting and a treasury.
