# Script — Record Types and Business Processes

## Segment 1 (title)

Picklist values, processes, and page layouts set on the same object can still differ sharply between kinds of records — a Question case has nothing to do with a Problem case's root-cause workflow. Record types are how one object offers genuinely different values, processes, and layouts per kind of record.

## Segment 2 (screenshot: Support Processes list)

For Case, Lead, and Opportunity specifically, a record type needs an associated process first. A process is a named, restricted subset of a key picklist's values — a Support Process restricts Case Status, a Sales Process restricts Opportunity Stage. You define these before you can attach them to a record type.

## Segment 3 (screenshot: New Record Type wizard)

Creating a record type means picking an existing one to clone picklist values from, a label and name, and for Case, Lead, and Opportunity, which process it uses. That Support Process dropdown is exactly where the process you defined earlier gets attached.

## Segment 4 (screenshot: Record Types list)

Every record type created for an object lands in its own list in Object Manager — active status, who last modified it — right alongside the processes list it references.

## Segment 5 (steps: what a record type bundles)

One record type bundles four things together: which picklist values are available, which page layout a profile sees, which business process governs the status field, and which profiles can even create this kind of record at all.
