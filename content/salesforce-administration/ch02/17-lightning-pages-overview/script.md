# Script — Lightning Pages Overview

## Segment 1 (title)

Everything so far in this chapter has been about which app and which tabs a user sees. This lesson zooms in one level deeper: the actual page a user lands on once they click a tab, and the tool that builds it — the Lightning App Builder.

## Segment 2 (screenshot: App Builder canvas)

A Lightning page is a custom layout built from components, and there are three types: Home Page, Record Page, and App Page. All three are built the same way — a component palette on the left, a live canvas in the center, drag and drop, no code required.

## Segment 3 (screenshot: Lightning Pages list)

Every Lightning page built in the org shows up on the Lightning App Builder's own setup list — label, name, type, who created and last modified it — with New, Edit, and Clone right there.

## Segment 4 (screenshot: Activation levels)

But building a page doesn't put it in front of anyone automatically. It has to be activated and assigned, and Salesforce resolves that at three levels: org default, which app default can override, which the most specific level — app, record type, and profile — can override again.

## Segment 5 (steps: the three page types)

Home Page for an app's landing tab. Record Page for a specific object's records. App Page for a freestanding page not tied to any record. Different jobs, same builder.
