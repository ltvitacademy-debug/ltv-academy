# Script — Administrator Case Study: Onboarding a Sales Team

## Segment 1 (title)

This last lesson doesn't introduce anything new. It walks through one realistic scenario — onboarding a new sales team at a fictional company, Meridian Fixtures Co. — and traces exactly which settings from this entire course an admin actually reaches for, in order, to make it happen.

## Segment 2 (steps: users and access)

Six new reps need to exist with the right access and nothing more. Reuse the existing BDR profile instead of building a new one — known-good beats improvised. Add two permission sets for the dialer tool and the New Logo record type. Match login hours and IP restrictions to the rest of the sales org.

## Segment 3 (steps: org and object configuration)

Add the team to the existing Sales Console app rather than building a new one — one less thing to maintain. Give the New Logo record type its own page layout with outbound fields up top. Filter the Opportunities related list to open deals only, so old closed-lost records don't bury today's live pipeline.

## Segment 4 (steps: communication and testing)

Point the team at the existing email template and letterhead — no new branding work. Build every change in a sandbox first, even though it feels routine, because it touches a shared page layout. Move it with a Change Set. On day one, check Login History to confirm all six reps logged in successfully — the fastest way to catch an access problem before a rep has to ask for help.
