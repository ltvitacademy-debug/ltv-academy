# Script — Notifications and Alerts

## Segment 1 (title)

Email templates and Chatter cover planned communication. But a lot of what users need is a quick heads-up the moment something happens — an opportunity closes, a case gets reassigned, an approval needs them. That's what Notifications and Alerts are for.

## Segment 2 (screenshot: Notification Builder navigation)

Custom notifications are built from Setup, under Notification Builder, Custom Notifications. That's where an admin defines a brand-new notification type from scratch.

## Segment 3 (screenshot: New Custom Notification Type)

Creating one asks for a Custom Notification Name, an API Name, and Supported Channels — Desktop, Mobile, or both. This example defines an "Opportunity Closed" notification for both channels.

## Segment 4 (screenshot: Custom Notification Types list)

Once saved, the type appears in the Custom Notification Types list, ready to be fired by automation — specifically a Flow or Process Builder, which is what actually sends it when the real-world event happens.

## Segment 5 (screenshot: notification bell dropdown)

And here's the payoff: the bell icon in the top nav badges with a count, and opening it shows the real message — "Opportunity Update: United Oil Installations is now closed!" — the exact text the Flow was built to send.

## Segment 6 (steps: four notification channels)

There are really four channels for getting a user's attention: the in-app bell, which needs no setup at all; mobile push, if the notification type supports it; email alerts, a separate, older mechanism built on templates; and custom notifications, the modern admin-defined type fired by automation.
