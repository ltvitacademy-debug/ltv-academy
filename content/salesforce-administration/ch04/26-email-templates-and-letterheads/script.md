# Script — Email Templates and Letterheads

## Segment 1 (title)

Every org already has an Email Templates object, and every admin ends up standardizing how their users send email from Salesforce — sales emails, case replies, renewal reminders. This lesson covers templates and the letterheads that brand them.

## Segment 2 (screenshot: App Launcher — find templates)

Users find Email Templates straight from the App Launcher search box — it's a standard item, no special setup needed just to see the list.

## Segment 3 (screenshot: permission set — Lightning Email Builder)

But the modern Lightning email builder isn't on by default. An admin creates a permission set, goes to System Permissions, and enables "Access drag-and-drop content builder" — without it, users only see the older plain editor.

## Segment 4 (screenshot: new template — Enhanced Letterhead)

Creating a new template asks for three things beyond the subject line: a Related Entity Type so merge fields can pull data from a record, a Folder for sharing and organization, and an Enhanced Letterhead — the shared header, footer, and branding every template in that letterhead wears.

## Segment 5 (screenshot: template detail — Edit in Builder)

Save the template, then click Edit in Builder. That opens the drag-and-drop canvas: text, image, button, and row components on the left, style and merge-field properties on the right.

## Segment 6 (steps: the admin's checklist)

Build the letterhead once — logo, colors, header and footer — and every template that uses it stays visually consistent without each author redoing the branding by hand. Templates then get reused everywhere: email alerts, Flow, approval processes, and manual sends from a record.
