# Lesson 24 — Governance Architecture Documentation · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

## S1 · TITLE

An architecture that only lives in one person's head or an old slide deck isn't an architecture anymore — it's folklore. This lesson is about documenting it so it survives.

## S2 · STEPS — Why documentation matters

Documentation is what lets a governance architecture survive turnover. A new architect or review board member should be able to read it and understand not just what was decided, but why. Most enterprise architecture practice treats a maintained architecture repository as core, because tribal knowledge doesn't scale past the people in the original room.

## S3 · STEPS — The core documentation set

The set generally covers five things: a principles catalog with rationale, the capability map showing what exists and what's missing, reference architecture diagrams kept current, a running decision log — which next lesson covers in depth — and pointers to the real standards and policies, not duplicated copies that drift.

## S4 · STEPS — Living documentation and versioning

The biggest failure isn't a missing document, it's one that was accurate the day it was written and wrong ever since. Treat it as living: owned, reviewed on a cadence, updated as part of making a decision. And keep minimum versioning — a last-updated date, a short change note, one stable location people know to check.
