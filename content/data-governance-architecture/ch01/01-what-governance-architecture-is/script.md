# Lesson 1 — What Governance Architecture Is · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

## S1 · TITLE

Data Governance Foundations covered governance itself — the decisions, the roles, the operating models. This course picks up a different question: how do you actually build the systems that make those decisions real?

## S2 · STEPS — Two different questions

Governance is the decision — who decides, and what the rule is. Governance architecture is the system that makes that decision actually happen, day to day, across dozens of platforms.

## S3 · STEPS — What architecture has to provide

Every real governance architecture provides three things: a metadata and catalog layer that holds what data means and where it came from, a policy and enforcement layer that turns a written rule into a running control, and an integration layer that connects it all.

## S4 · STEPS — Where this fits

Governance architecture is a specialized domain inside enterprise architecture, the same way security architecture is. It doesn't replace the operating-model decisions from Foundations — it implements them.

## S5 · CODE — The stack this course builds

Picture it as a stack. The operating model sits on top — who decides, covered in Foundations and revisited in this course's Chapter 2. Governance architecture sits underneath, built from metadata, policy, access, lineage, and integration.
