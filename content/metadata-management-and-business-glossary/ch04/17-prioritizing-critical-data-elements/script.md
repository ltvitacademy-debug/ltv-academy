# Lesson 17 — Prioritizing Critical Data Elements · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

---

## S1 · TITLE CARD

Lesson 16 gave you a yes-or-no test: is this element critical? In a
real organization, that test often returns yes for more elements than
anyone can realistically govern with equal intensity — forty CDEs is
common at a mid-sized company.

## S2 · STEPS CARD (the real question)

At that point the question shifts from "is this critical" to "which of
our critical elements needs attention first." Prioritization turns a
long flat list of CDEs into something actually actionable.

## S3 · STEPS CARD (two axes)

Score each CDE on two independent axes. Impact — how bad is it if this
element is wrong, reusing Lesson 16's four criteria. Likelihood — how
probable is it this element is actually wrong right now, given how it's
sourced and validated.

## S4 · CODE CARD (worked ranking)

Here's a worked ranking. OrderTotal: high impact, medium likelihood —
high priority. TaxRate: high impact, but low likelihood since it comes
from a single validated reference table — medium priority.
SalesRepNotes: low impact, high likelihood — low priority, even though
it's the most error-prone of the three.

## S5 · OUTRO CARD

OrderTotal tops the list not because it's the single highest-impact
element, but because it combines real impact with meaningful error
risk. Next lesson: critical data element documentation — what a
top-priority CDE's record actually needs.
