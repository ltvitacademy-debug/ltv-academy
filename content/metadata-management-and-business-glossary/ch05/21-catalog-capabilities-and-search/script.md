# Lesson 21 — Catalog Capabilities and Search · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

---

## S1 · TITLE CARD

A catalog with perfect metadata that nobody can actually find is
worthless — the same publish failure mode from the metadata lifecycle,
specific to catalogs. The entire value collapses into one question:
when someone searches, do they find the right answer quickly?

## S2 · STEPS CARD (four capabilities)

Four capabilities separate a useful catalog from a glorified
spreadsheet. Full-text search across both business and technical
metadata. Faceted filtering by owner, system, status, or sensitivity.
Relationship navigation between glossary and dictionary. And
usage-based ranking, surfacing what's actually queried above what
nobody touches.

## S3 · STEPS CARD (why faceted search matters)

A general web search mostly works on relevance alone, because the web
doesn't have a reliable owner or status field to filter on. A data
catalog does — because Chapters 2 through 4 spent enormous effort
getting those fields documented consistently. Faceted search is where
that upfront investment actually pays off.

## S4 · CODE CARD (worked search)

A new analyst searches "customer revenue." A good result set surfaces
the Net Revenue glossary term first, then OrderTotal — which implements
it and is heavily used — then a related Customer Lifetime Value term. A
poorly built catalog just returns every table with "customer" in its
name, unsorted.
