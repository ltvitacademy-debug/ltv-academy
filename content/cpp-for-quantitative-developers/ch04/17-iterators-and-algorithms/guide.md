# Iterators & Algorithms

In the last lesson you saw four different containers with four different internal layouts. Yet `std::sort` works on a `vector`, and `std::accumulate` works on a `deque`, with no container-specific code at all. **Iterators** are the abstraction that makes this possible — and the ~100 algorithms in `<algorithm>` are written entirely in terms of them.

## What you'll learn

- What an iterator actually is, and the `begin()`/`end()` half-open range convention
- `std::sort`, `std::find`, and `std::accumulate` as the three algorithms you'll use constantly
- Iterator categories (forward, bidirectional, random-access) and why they limit which algorithms apply
- Range-based `for` as iterator syntax you've already been using

## What an iterator is

An iterator is an object that behaves like a generalized pointer: `*it` dereferences to the current element, `++it` advances it. `begin()` returns an iterator to the first element; `end()` returns an iterator to *one past* the last element — a deliberate "half-open range" convention so an empty range is simply `begin() == end()`.

```cpp
std::vector<double> prices{101.25, 99.80, 103.10};
for (auto it = prices.begin(); it != prices.end(); ++it) {
    std::cout << *it << "\n";
}
```

A range-based `for` loop (`for (const auto& p : prices)`) is exactly this pattern, generated by the compiler — you've been using iterators all along without the explicit syntax.

## Algorithms operate purely through iterators

Because `std::sort` is written against iterators, not against `std::vector` specifically, it works on *any* container whose iterators support random access — which is the whole point: one algorithm, many containers.

```cpp
#include <algorithm>
#include <vector>

std::vector<double> prices{101.25, 99.80, 103.10, 97.50};
std::sort(prices.begin(), prices.end());
// prices is now: 97.50, 99.80, 101.25, 103.10

auto it = std::find(prices.begin(), prices.end(), 101.25);
if (it != prices.end()) {
    std::cout << "Found at position " << (it - prices.begin()) << "\n";
}
```

## `std::accumulate` for reductions

`std::accumulate` (in `<numeric>`) folds a range down to a single value — the classic use is a sum, but it accepts a custom binary operation too.

```cpp
#include <numeric>

std::vector<double> prices{101.25, 99.80, 103.10};
double total = std::accumulate(prices.begin(), prices.end(), 0.0);
double avg = total / prices.size();
```

The `0.0` is the initial value the fold starts from — always pass a value of the correct type (`0.0`, not `0`, for a `double` sum) to avoid silent truncation.

## Iterator categories limit which algorithms apply

Not every iterator supports every operation. A `std::list` iterator supports `++` and `--` (bidirectional) but not jumping forward by `n` in O(1), so `std::sort` — which needs random access — cannot be called on a `std::list` directly; `std::list` provides its own `sort()` member function instead.

| Category | Supports | Example container |
|---|---|---|
| Forward | `++it` only | `std::forward_list` |
| Bidirectional | `++it`, `--it` | `std::list`, `std::map` |
| Random-access | `it + n`, `it[n]` | `std::vector`, `std::deque` |

## Key terms

| Term | Meaning |
|---|---|
| Iterator | A generalized pointer-like object for traversing a container |
| `begin()` / `end()` | Half-open range: `end()` points one past the last valid element |
| `std::sort` | Sorts a random-access range in place |
| `std::accumulate` | Folds a range into a single value (`<numeric>`) |
| Iterator category | Forward / bidirectional / random-access — determines which algorithms apply |

## Recap

Iterators decouple algorithms from containers: `std::sort`, `std::find`, and `std::accumulate` all operate purely on a `begin()`/`end()` range, which is why the same three lines of algorithm code work across `vector`, `deque`, and beyond. Next up, Lesson 18: Strings, Streams & I/O.
