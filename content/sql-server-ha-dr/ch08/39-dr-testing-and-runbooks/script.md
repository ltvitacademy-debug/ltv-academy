# Script — DR Testing & Runbooks

## Segment 1 (title)

A DR plan sitting untested in a shared drive is a hypothesis, not a plan. This lesson covers why testing is non-negotiable, the two real levels of testing, and what separates a runbook that works during a real incident from one that just looks thorough on paper.

## Segment 2 (code: two levels of testing)

A tabletop exercise is a talk-through of the plan — low cost, low risk, and good at validating the plan's logic and roles. A real failover drill actually executes recovery — higher cost and risk, but it validates whether the technical steps actually work. Most organizations need both.

## Segment 3 (steps: a good runbook)

A good runbook uses actual commands, not vague instructions. It specifies exact file paths, server names, and access needed. And it includes verification steps after each action, confirming the recovery actually worked, not just that it ran.

## Segment 4 (outro)

Testing and runbook quality reinforce each other — a tabletop reveals if a step is even right, a real drill reveals if the exact command still works. Next up: how geography — distance, latency, and data residency — shapes real DR site decisions.
