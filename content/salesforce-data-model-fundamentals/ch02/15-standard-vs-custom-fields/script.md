# Script — Standard vs. Custom Fields

## Segment 1 (title)

Every field this chapter has shown could be either standard, built in by Salesforce, or custom, built by an admin. Day to day they behave almost identically — this lesson names the actual structural differences.

## Segment 2 (screenshot: fields list)

Every object's Fields and Relationships list mixes standard and custom fields together, with no separate tab and no visual separation. Account Name and Account Number here are standard; custom fields join the same table further down.

## Segment 3 (screenshot: rename label)

A standard field's data type is fixed — you can't turn it into a Picklist. What you can change is its label: Rename Tabs and Labels lets you relabel Rating as Prospect Rating, while the field's API name and core behavior stay exactly what Salesforce defined.

## Segment 4 (screenshot: new field data types)

Compare that to a brand-new custom field: Step 1 offers the entire Data Type menu, every family this chapter covered, because nothing about a field that doesn't exist yet is locked in.

## Segment 5 (outro)

One reliable tell even without a dedicated column: a custom field's API name always ends in two underscores and a c. Chapter 2 is done — next, Chapter 3 opens with relationships: lookup and master-detail.
