Page layouts and compact layouts both predate Lightning's real page-building tool. This lesson covers that tool directly: Lightning App Builder, the drag-and-drop canvas behind every modern Salesforce page.

Every Lightning page you build uses the same five-part layout. The page name up top. A toolbar for save, undo, and activation. The Components panel on the left, listing everything you can drag on. The canvas in the middle, where the page actually takes shape. And a Page properties panel on the right for page-level settings.

Building a page is drag, drop, configure. Drag a component — a list view, a report chart, a related list — from the palette onto the canvas. Then use the panel on the right to set exactly which object or filter it's bound to. No code at any point in that sequence.

Lightning App Builder actually builds three different kinds of page. An App Page is a custom home page for one specific app. A Record Page overrides the standard layout for one object — this is what's steadily replacing page layouts. And a Home Page replaces the org-wide Lightning home screen entirely.

And here's that exact canvas, live: a list view and a set of recent opportunities, both pulling real data straight from the org. Nothing behind either one but the configuration you just saw get dragged into place.
