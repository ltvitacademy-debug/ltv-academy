# Lesson 8 — Data Governance Frameworks Compared · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

## S1 · TITLE

DMBOK isn't the only named framework in real use. Three more come up constantly — each solving a different piece of the puzzle.

## S2 · STEPS — Three more frameworks, three different jobs

DCAM, built for maturity benchmarking. COBIT, built for IT governance, with data governance as part of its scope. ISO 38505, built for board-level accountability. Picking one because it's well-known instead of because it fits the problem is the common mistake.

## S3 · STEPS — DCAM

Developed by the EDM Council, DCAM assesses current data management capability across defined components and produces a maturity profile — the basis for a roadmap. Its strength is benchmarking. Its tradeoff: assessment-heavy, less prescriptive about exactly how to execute the fix.

## S4 · STEPS — COBIT and ISO 38505

COBIT, maintained by ISACA, is an IT governance framework with data governance as one component inside it — a strong fit when data governance needs to plug into an existing IT governance structure. ISO 38505 operates at a higher altitude still: it frames data governance as a board-level responsibility, not an operational concern.

## S5 · STEPS — Combining them in practice

Most real programs borrow from more than one. ISO 38505 establishes the board mandate. DCAM or DMBOK supplies the operational structure underneath it. COBIT comes in specifically where data governance needs to integrate with broader IT governance.
