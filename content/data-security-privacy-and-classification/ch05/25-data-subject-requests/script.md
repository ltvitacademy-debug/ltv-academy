# Lesson 25 — Data Subject Requests · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

---

## S1 · TITLE CARD

Erasure, from last lesson, is one of several rights an individual —
a data subject — can invoke over their own personal data. This
lesson covers the full set, and how an organization actually fulfills
one of these requests.

## S2 · STEPS CARD (the rights)

The common set includes access — a copy of the data held about them —
rectification, correcting inaccurate data, erasure, portability —
receiving their data to move elsewhere — restriction, and objection.
Treating every one of these as the same generic bucket is a mistake;
an access request and a portability request expect different outputs.

## S3 · STEPS CARD (the four-step process)

Regardless of which right is invoked, the process is the same four
steps. Verify identity first — skipping this turns a privacy right
into an attack vector. Locate the data across every system that holds
it. Compile and respond within the applicable window. And log the
request, independent of the data itself, as proof it was honored.

## S4 · STEPS CARD (why it's hard)

Locating the data is usually where this breaks down. Personal data is
rarely in one table — it's in the application database, a warehouse
copy, a CRM, support tools, log files, and sometimes spreadsheets
nobody officially sanctioned. A credible process depends on already
knowing where personal data lives, which is exactly what classification
and a data inventory exist to make possible.

## S5 · OUTRO CARD

Next lesson: auditing and logging — the record that proves any of this,
from access control to DSR fulfillment, actually happened the way you
