# Script — Shift-Left Security

## Segment 1 (title)

Welcome to DevSecOps Fundamentals. Across this course you'll follow Northbridge Retail, a mid-size e-commerce retailer, as its platform team builds security into how software gets shipped, instead of bolting it on at the end. This lesson introduces the idea the course is named after: shifting security left.

## Segment 2 (steps)

Picture a delivery timeline running left to right: plan, code, build, test, deploy, operate. Shifting left means moving security activities toward the early side of that timeline. The same bug costs seconds to fix in the editor, one more commit in code review, a dependency bump in the pipeline, or a full incident response if it's found in production. The flaw doesn't change — only how expensive and risky it is to catch gets worse the later it's found.

## Segment 3 (steps)

DevOps unified development and operations around shared pipelines. SecOps is security's operational side: monitoring and responding to threats against systems already running. DevSecOps goes one step further, weaving automated security checks directly into the same pipeline developers already use, so guardrails run on every commit instead of relying on someone remembering to review for them.

## Segment 4 (steps)

Over this course, you'll see this applied concretely at Northbridge Retail: threat modeling before code is written, least-privilege identity for every service, secrets that never sit in plaintext, and automated scanning before anything merges. Chapter 6 covers what happens when something still slips through anyway.

## Segment 5 (outro)

Shifting left doesn't make a retailer invulnerable — it moves discovery earlier, where fixing things is cheap. Next up, lesson two: threat modeling basics.
