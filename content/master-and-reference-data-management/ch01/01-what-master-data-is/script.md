# Lesson 1 — What Master Data Is · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

---

## S1 · TITLE CARD

Master data management: the discipline of getting one organization to agree
on who its customers, products, vendors, and employees actually are. This
course spends twenty-five lessons on exactly that problem.

## S2 · STEPS CARD (three traits)

Master data is the core set of entities multiple systems reuse — customers,
products, vendors, employees, locations. Three traits set it apart: it's
reused across many processes, not generated once; it changes slowly,
unlike a transaction log; and it's relatively low in volume but very high
in value — get one customer record wrong, and every order tied to it
inherits the mistake.

## S3 · CODE CARD (same customer, three systems)

Picture one real customer, seen three different ways: the CRM has "Robert
Chen," the billing system has "Bob Chen" with an updated address, the
shipping system has "R. Chen" with an address from two years ago. Each
system is correct about something. None of them, alone, answers "who is
this customer, right now?"

## S4 · STEPS CARD (why it matters)

This shows up the moment it matters most: a merger duplicating half a
product catalog, a marketing campaign mailing the same person three
times, an opt-out that doesn't stick because it only applied in one
system. Master data problems are invisible until they're suddenly very
visible.

## S5 · OUTRO CARD

Next: how master data is different from reference data and transactional
data — three categories that get confused constantly, and a clean way to
tell them apart.
