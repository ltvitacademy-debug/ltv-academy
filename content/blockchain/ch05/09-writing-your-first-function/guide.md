# Lesson 9 — Writing Your First Function: setMessage

**Chapter 5 · Solidity Programming · Lesson 9 of 10**

> Real classroom footage from the LTV Academy Blockchain Development course, taught by instructor Harris Lavine, live-coding in the actual Remix IDE.

## What you'll learn

- How to actually write a function that changes a contract's state
- Why the `memory` keyword is required for string parameters
- The real naming convention (camelCase) used for functions
- How to call a deployed function and watch state actually change

## The real problem: a message you can't update

The `Hello` contract from earlier lessons could only ever say `"Hello
class"` — there was no way to change it after deployment. This lesson's
real goal: write a function that lets anyone update that message.

## Defining the function, piece by piece

![The actual `setMessage` function, typed live in class: `function setMessage(string memory newMessage) public { message = newMessage; }`.](/courses/blockchain/ch05/09-writing-your-first-function/shot_setmessage_function.png)
*The real function signature from class — name, parameter, and visibility, all in one line.*

```solidity
function setMessage(string memory newMessage) public {
    message = newMessage;
}
```

- **`function`** — the keyword that starts every function definition.
- **`setMessage`** — the function's name. Real style convention: start
  lowercase, then capitalize each following word (**camelCase**) — not
  mandatory, but what most Solidity code actually follows.
- **`(string memory newMessage)`** — the function's **input**. It takes
  a `string`, deliberately named differently from the contract's own
  `message` variable to avoid confusion.
- **`memory`** — required whenever you pass certain types (like
  strings) into a function. Solidity needs to know **where the data
  lives**: `storage` is permanent and expensive (recorded on-chain),
  `memory` is temporary (cleared after the function call ends), and
  `calldata` is read-only input, typically for external functions.
- **`public`** — same meaning as before: anyone can call this function.
- **No semicolon after the function signature** — just like a contract
  definition, a function opens and closes with curly braces instead.

## What the function body actually does

![The completed function body from class, showing the actual assignment: `message = newMessage;` — the state variable now updated by whatever the function receives.](/courses/blockchain/ch05/09-writing-your-first-function/shot_function_body.png)
*The real, one-line function body: taking the input and assigning it to the contract's own state variable.*

Inside the curly braces, one line: `message = newMessage;` — it takes
whatever string was passed in and assigns it to the contract's real
`message` state variable, permanently changing what the contract stores.

## Watching it actually work

After compiling and deploying, Remix shows two real, separate controls:

- A **getter function** for `message` (blue) — auto-generated by
  Solidity because the variable is `public`. Pressing it returns the
  current value.
- A **`setMessage`** function (orange) — since it takes an input, Remix
  requires you to type a string into a text box before you can press
  **transact**.

Typing `"this is my new message"` and pressing transact gets a real
green checkmark — and pressing the getter again now returns the new
value. That's a real, live state change, recorded on the blockchain.

## Key terms

| Term | Meaning |
|---|---|
| Function parameter | The input data a function receives when called |
| memory | A data location keyword — temporary storage, cleared after the function call |
| Getter function | An auto-generated function that reads a public variable's current value |
