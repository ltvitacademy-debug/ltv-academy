# Lesson 1 — Cloud Data Governance Overview · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

## S1 · TITLE

Welcome to Cloud Data Governance: Azure and AWS. This lesson sets up what changes — and what doesn't — when governance moves to the cloud.

## S2 · STEPS — What the cloud changes

Everything from the Data Governance Foundations course still applies — decision rights, stewardship, policy. What changes is the terrain. Anyone with console access can provision storage in minutes, no procurement review required. The shared responsibility model splits accountability — the provider secures the infrastructure, but you always own access control and classification. Governance has to be expressed as enforceable policy, not a memo nobody checks. And sprawl happens fast — a single account can hold thousands of resources within months.

## S3 · STEPS — Why both Azure and AWS

Most organizations aren't single-cloud by design — they're multi-cloud by accumulation: an acquisition brought AWS accounts, a partnership required an Azure tenant. The underlying governance concepts — identity, hierarchy, policy, encryption — are the same ideas under different names. Knowing only one cloud's console makes you half as useful as someone who knows both.

## S4 · STEPS — Where this course goes

Chapter one stays architectural — shared responsibility, landing zones, consistency across environments. Chapter two goes hands-on with identity: Entra ID, Azure RBAC, AWS IAM. Chapter three covers where governed data lives and how it's cataloged. Chapter four covers encryption, compliance, and policy engines. Chapter five closes with the hardest problem: governing data that spans both clouds at once.
