# Lesson 20 — System Architect Exam Domains

**Chapter 4 · Practice · Lesson 20 of 22**

## What you'll learn

- How the Salesforce Certified System Architect credential is structured, at a high level
- Why it's built from several individual certification exams rather than one single test
- How the System Architect track differs in emphasis from the Application Architect track
- Why you should always confirm current exam names, prerequisites, and scoring directly with Salesforce before registering

## An overlay credential, not a single exam

The Salesforce Certified System Architect credential is commonly described as a multi-exam, overlay-style credential: rather than sitting one System Architect exam, a candidate earns a defined set of individual architecture certifications, and the System Architect credential itself is awarded once that full set is held simultaneously in active status. This structure matters conceptually even before you memorize a specific list, because it tells you something true about the discipline: System Architecture isn't one skill, it's a named combination of several distinct architecture competencies, each substantial enough to be certified on its own.

## The domains this credential's exams tend to cover

Across the material this course has covered, the individual exams that make up the System Architect track are consistently described as covering territory like: **integration architecture** (the patterns and boundary decisions from Chapters 1 and 3 of this course), **identity and access management architecture** (the enterprise identity landscape from Lesson 14), and **development lifecycle and deployment architecture** (release management, sandbox strategy, and environment planning from Lesson 18), typically alongside a developer-level prerequisite credential demonstrating hands-on platform depth. This lines up closely with the material this course has taught: integration boundaries, enterprise identity, and roadmap/release sequencing are not side topics here, they're direct preparation for the actual certification domains.

## How it differs from the Application Architect track

Salesforce also offers an Application Architect overlay credential, built from a different but overlapping set of individual exams, commonly described as covering data architecture, sharing and visibility architecture, alongside the same integration and identity exams the System Architect track also draws on. The practical distinction practitioners describe is one of emphasis: Application Architecture leans toward how a single, often complex, Salesforce implementation is designed internally (data model, sharing, visibility), while System Architecture leans toward how Salesforce fits into and interacts with everything around it (integration, identity across systems, release and environment strategy) — which is exactly the distinction Lesson 1 opened this entire course with.

## Verify before you register

Because exam names, prerequisites, question formats, and passing scores are controlled entirely by Salesforce and do change over time, and because even recent third-party sources disagree on some specifics, the responsible habit for any candidate is to treat this lesson as orientation, not as a substitute for Salesforce's own current certification pages. Before registering for any exam in this track, confirm directly on Salesforce's official certification site: the exact current prerequisite exams, the current question count and format, the current passing score, and the current registration fee. Building a study plan around a third-party blog's possibly-outdated numbers is a preventable mistake.

## Key terms

| Term | Meaning |
|---|---|
| Overlay credential | A certification awarded automatically once a candidate holds a defined set of other certifications simultaneously, rather than through one dedicated exam |
| Integration Architect (domain) | The architecture domain covering integration patterns and boundary decisions between systems |
| Identity and Access Management Architect (domain) | The architecture domain covering enterprise identity, SSO, and provisioning design |
| Development Lifecycle and Deployment Architect (domain) | The architecture domain covering release management, environment, and sandbox strategy |
