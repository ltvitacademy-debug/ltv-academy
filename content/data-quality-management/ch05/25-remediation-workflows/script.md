# Lesson 25 — Remediation Workflows · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

## S1 · TITLE

Lesson twenty-five turns root cause analysis and cleansing into a repeatable process — a remediation workflow an organization can actually run every week.

## S2 · STEPS — WHY A WORKFLOW

Without a workflow, remediation is ad hoc — whoever notices a problem fixes it their own way, nothing gets tracked, and the same issue quietly comes back because no one closed the loop.

## S3 · STEPS — FIVE STAGES

Five stages, most workflows share them: detect, a rule or monitor finds a violation; triage, decide severity; assign, route it to whoever owns the data; fix, root cause and cleansing; and verify — re-run the original check to confirm it's actually gone.

## S4 · STEPS — AUTOMATED VS MANUAL

Not every fix deserves the same judgment. Automated remediation handles high-volume, well-understood patterns fast — but a bad rule can mass-corrupt data just as fast. Manual remediation handles ambiguous, higher-risk cases, one at a time.

## S5 · STEPS — FIX AT THE SOURCE

Cleansing only in the warehouse is faster to build, but every downstream copy still carries the bad value, and you re-apply the fix on every load forever. Fixing the source system means the data arrives correct everywhere, the first time.

## S6 · STEPS — THE THREAD THROUGH THIS COURSE

This workflow ties the course together: detect from your rules and monitoring, triage from your thresholds, fix from root cause and cleansing, verify by re-running the check — then the whole cycle gets logged as a trackable issue.
