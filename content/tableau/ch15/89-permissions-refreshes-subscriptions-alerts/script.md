# Script — Permissions, Refreshes, Subscriptions, Alerts & Sharing

## Segment 1 (title)

Once content is published, five things determine what happens next: who can do what with it, how its data stays current, and how people find out about it without having to go check. Permissions, refreshes, subscriptions, alerts, and sharing.

## Segment 2 (screenshot: permission rules)

This is a real permission-rules grid from Tableau's own documentation — groups and users down the side, capabilities across the top, each cell Allowed, Denied, or left unspecified. Templates like View, Explore, and Administer set a whole row at once. The one rule that matters most: Deny always wins. If any rule denies a capability, that overrides an Allow from anywhere else.

## Segment 3 (screenshot: watch menu — subscriptions and alerts)

This Watch menu, straight from Tableau's documentation, is where subscriptions and alerts both live. A subscription emails a snapshot of a view on a fixed schedule — Monday morning, every week, automatically. A data-driven alert is different: it watches a number and notifies someone the instant it crosses a threshold you define, which is exactly what this Create Alert dialog configures — a condition, a threshold, and recipients.

## Segment 4 (steps: refreshes and sharing)

If a data source is an extract, it needs a refresh schedule to stay current — full or incremental, on whatever cadence the business needs, using the refresh access Lesson 88 set up. And sharing a link isn't the same as granting a permission — sharing just gets someone to the door; the permission rule decides whether they actually get in.
