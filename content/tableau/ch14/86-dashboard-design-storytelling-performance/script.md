# Script — Dashboard Design, Storytelling & Performance

## Segment 1 (title)

This chapter built dashboards, layout, KPI headers, actions, navigation, and device design. This lesson closes it out with the judgment calls that tie all of it together: storytelling, decluttering, and performance.

## Segment 2 (screenshot: clean filter panel and table)

Storytelling on a dashboard isn't decoration — it's controlling the order a viewer's eye lands on information. You already have every tool for it: a KPI header that lands first, actions that let a viewer follow their own question, a layout that puts the headline above the detail. This real Tableau example shows the other half — restraint. Every color, every filter here has a reason. Nothing is decorative.

## Segment 3 (screenshot: Range sizing)

Performance is the other half of good design. A live connection re-querying on every filter change, too many Hover-triggered actions, an unbounded canvas — these all make a dashboard feel slow. A bounded Range size, like this one, keeps the canvas predictable for both design and rendering.

## Segment 4 (steps: where performance problems actually come from)

A slow dashboard is usually a symptom of a decision made chapters earlier — a live connection instead of an extract, quick filters instead of context filters, Automatic instead of Range sizing. Performance isn't a separate skill from everything else in this course, it's a consequence of it.
