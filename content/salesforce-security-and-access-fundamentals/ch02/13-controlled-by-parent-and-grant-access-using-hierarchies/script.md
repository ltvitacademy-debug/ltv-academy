# Script — Controlled by Parent and Grant Access Using Hierarchies

## Segment 1 (title)

Two settings have been sitting quietly in the screenshots since Lesson 7. This lesson, the last in Chapter 2, explains both properly — Controlled by Parent and Grant Access Using Hierarchies.

## Segment 2 (screenshot: OWD page)

Controlled by Parent means exactly what it says — that object has no independent OWD of its own. A user's access to a Contact is whatever their access to that Contact's parent Account already is. See the Account, see the Contact. There's no separate sharing model to configure, because the object is designed to inherit access entirely from the relationship it belongs to.

## Segment 3 (screenshot: Reviewers group)

Grant Access Using Hierarchies has appeared on OWD rows and on a group's own detail page — it's the same setting in both places, controlling whether the role hierarchy is allowed to apply to that sharing at all. On by default, locked for most standard objects, and rarely turned off deliberately.

## Segment 4 (screenshot: New Public Group)

It shows up again right at group creation time, confirming it's a property of the sharing recipient itself, not a one-time OWD toggle you set once and forget.

## Segment 5 (steps: chapter recap)

Seven lessons, one stack: OWD sets the floor, or hands it off entirely via Controlled by Parent. The role hierarchy widens it upward automatically, if Grant Access Using Hierarchies allows it. Sharing rules widen it to configured groups. Manual sharing widens it one record at a time. And teams, public groups, and queues round it out — standing collaboration and the reusable containers several of these mechanisms point at.

## Segment 6 (outro)
