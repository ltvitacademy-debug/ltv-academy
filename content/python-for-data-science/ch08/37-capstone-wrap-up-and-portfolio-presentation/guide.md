## Step 1: lead with the answer

Stakeholders don't want your process; they want your conclusion, then the evidence. A useful structure:

1. **Headline:** one sentence that answers the question.
2. **Evidence:** two or three numbers or one chart that support it.
3. **So what:** the action this suggests.
4. **Caveats:** what could make you wrong.
5. **Next steps:** what you'd do with more time or data.

Here is how our capstone reads. *(These conclusions come from our illustrative dataset.)*

- **Headline:** Revenue is concentrated in the North region, in Electronics, and in the fourth quarter. Discounts did not increase items per order, and returns were higher on discounted orders.
- **Evidence:** About $184K from 1,267 completed orders; Q4 is 34.6% of revenue; average quantity is roughly 3 in every discount band, while return rates run from 7.2% (no discount) to 12.6% (21-30% off).
- **So what:** Plan inventory and staffing ahead of Q4, and review whether deep discounts are worth their return cost.
- **Caveats:** The deepest discount band has only 103 orders; this is association, not proof of cause. We dropped about 4% of deduplicated rows for invalid quantities and assumed a missing discount meant zero.
- **Next steps:** Test the discount effect with a proper experiment or a statistical test, and confirm the quantity rule with the shop.

Notice that the caveats make the analysis more credible, not less.

## Step 2: pull numbers from code

Never retype numbers into a report by hand. Compute them once, from the cleaned file:

```python
import pandas as pd

clean = pd.read_csv("data/clean/orders_clean.csv", parse_dates=["order_date"])
clean["month"] = clean["order_date"].dt.to_period("M")
sales = clean[clean["status"] == "complete"]
monthly = sales.groupby("month")["revenue"].sum()

summary = {
    "orders": len(sales),
    "revenue": round(sales["revenue"].sum()),
    "q4_share_pct": round(
        monthly[monthly.index.month >= 10].sum() / monthly.sum() * 100, 1
    ),
    "top_region": sales.groupby("region")["revenue"].sum().idxmax(),
    "top_category": sales.groupby("category")["revenue"].sum().idxmax(),
}
print(summary)
```

On our data this prints `{'orders': 1267, 'revenue': 183979, 'q4_share_pct': 34.6, 'top_region': 'North', 'top_category': 'Electronics'}`. Because the raw data is seeded and the pipeline is code, rerunning it always reproduces these figures. (Reading the clean CSV back loses the `month` column's type, so we recompute it.)

## Step 3: write the README

A README is the front door of your project. Keep it short and scannable:

```markdown
# Retail Orders: Cleaning and Analysis

**Question:** Where does revenue come from, and do discounts work?
**Data:** Illustrative retail orders (1,530 raw rows), generated by make_data.py.

## Key findings
- North, Electronics, and Q4 drive revenue (Q4 = 34.6%)
- Discounts did not raise items per order; returns were higher on discounted orders

## How to run
1. python -m venv .venv and activate it
2. pip install -r requirements.txt
3. python make_data.py
4. Run analysis.ipynb (Restart & Run All)

## Assumptions and limits
- Quantities 1 to 20 kept; missing discount treated as 0 (flagged)
- Illustrative data: findings show the method, not real business results
```

Being honest that the data is illustrative is a strength. Hiring managers value clear limits far more than inflated claims.

## Step 4: portfolio checklist

Before you publish your repository, confirm:

- **Runs from scratch:** a fresh clone plus the README steps reproduces your results.
- **`requirements.txt` and seeds** are in place (lesson 34).
- **Tests pass** and cover your key cleaning functions (lesson 33).
- **The notebook is clean:** headings, small functions, Restart & Run All succeeds (lessons 31-32).
- **No secrets or private data:** no passwords, API keys, or customer data in the repo.
- **Findings up top:** the README leads with the answer and a chart.

If you're comfortable with Git, push the project to a public GitHub repository; the Git & GitHub course in this catalog covers that workflow.

## Step 5: present it in five minutes

Practice a walkthrough: the business question (30 seconds), what was wrong with the data and how you handled it (1 minute), the two findings with the chart (2 minutes), caveats and next steps (1 minute), and questions. In interviews, describe decisions rather than syntax: *why* you set a quantity rule, *how* you tested it, and *what* you'd check next.

When you're ready, repeat the whole workflow on a real public dataset (sources such as Kaggle, the UCI Machine Learning Repository, or government open-data portals; check each dataset's license). A second project shows the method wasn't a one-off.
