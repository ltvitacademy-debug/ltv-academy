# Script — Web Scraping Basics

Sometimes the data you need is on a web page, with no API and no download button. Web scraping means fetching that page and extracting the data with code. It's powerful, and it comes with responsibilities, so we start with those.

Before you write any code, ask four questions. Is there an official API or download? Use that instead. What does the site's robots dot txt file say about automated access? What do the terms of use allow? And can you scrape gently, with a clear user agent and pauses? Robots dot txt is a convention, not a law, and terms can forbid scraping entirely. This isn't legal advice, so when in doubt, ask, or don't.

We'll practice on Books to Scrape, a fictional bookstore built for learning. Python's standard library can read robots dot txt for you, and can fetch returns True. That site publishes no robots file, and describes itself as a scraping sandbox. Then request the page, identifying yourself in the user agent header.

The response text is HTML. Beautiful Soup parses it into a searchable tree. Select finds every element matching a CSS selector. Here that's twenty product cards. From a card, you read an attribute like the title, or call get text to read the visible text, such as the price.

Loop over the cards, build one dictionary per book, and pass the list to the DataFrame constructor. Now the cleaning skills apply. The price arrives as text with a pound sign, so strip the symbol and convert it. Across twenty books, the average price came to about thirty-eight pounds.

Scrapers are fragile. If the site changes its layout, your selectors stop matching. If content is generated by JavaScript, requests only sees the empty shell. If you're blocked or asked to stop, slow down or stop. For several pages, loop with a pause between requests. For simple HTML tables, read HTML does it in one call.
