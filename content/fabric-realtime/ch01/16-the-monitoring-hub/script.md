# Lesson 16 — The Monitoring Hub · Voiceover script

Segments map 1:1 to slides. Target: ~2.5-3 minutes total.

---

## S1 · TITLE CARD

Where does every item's activity actually show up? The
monitoring hub.

## S2 · CODE CARD (one place)

Databricks Lesson 11 covered run history, per job. Fabric's
monitoring hub does the same job, but across every item type at
once — notebooks, pipelines, dataflows, and eventstreams later
on — all in one unified list.

## S3 · CODE CARD (what a row shows)

One row shows the item, its type, status, start time, and
duration — filterable by any of those. Genuinely useful as a
first stop for did last night's pipeline actually run.

## S4 · CODE CARD (the parallel)

And drilling into a failed run shows the real error, which step
failed, and what downstream work never even got a chance to run —
the same triage instinct as reading the actual error before
guessing.

## S5 · OUTRO CARD

What ran, when, did it succeed — the same question Databricks'
run history answers, just at tenant scope here. Chapter 1
complete. Next: real-time data engineering, after one quick
recap.
