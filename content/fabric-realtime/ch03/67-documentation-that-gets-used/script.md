# Lesson 67 — Documentation That Actually Gets Used · Voiceover script

Segments map 1:1 to slides. Target: ~2.5-3 minutes total.

---

## S1 · TITLE CARD

Documentation that actually gets used — why most of it rots, and
what actually prevents that.

## S2 · CODE CARD (the runbook)

A runbook is a specific, step-by-step response to a specific alert
— what to do right now, at 2am. It survives because it gets opened
during a real incident, and its gaps get fixed immediately.

## S3 · CODE CARD (docs next to code)

A wiki page lives apart from the code and rots. A README in the
same folder as an eventstream gets updated in the same pull
request as a change to it — impossible to miss during review.

## S4 · STEPS CARD (what prevents rot)

Proximity or enforcement, not good intentions. A runbook survives
because it's read. A README survives because it's reviewed
alongside the change. A data contract survives because CI checks
it automatically.
