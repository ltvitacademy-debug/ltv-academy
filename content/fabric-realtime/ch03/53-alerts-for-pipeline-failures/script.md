# Lesson 53 — Setting Up Alerts for Pipeline Failures · Voiceover script

Segments map 1:1 to slides. Target: ~2.5-3 minutes total.

---

## S1 · TITLE CARD

Setting up alerts for pipeline failures — a different category
from activator's data alerts.

## S2 · CODE CARD (what deserves a page)

An eventstream disconnecting or a notebook exception deserves a
page right now. A single quality-check failure, already routed
elsewhere, or a slightly slow query can just be logged and
reviewed later.

## S3 · CODE CARD (alert fatigue)

If every minor blip pages someone, people start ignoring pages
entirely — including the one time it's real. That's alert
fatigue, and it's the most common reason alerting systems actually
fail.

## S4 · STEPS CARD (severity tiers)

Severity tiers match the response to the actual stakes. Sev one
pages immediately. Sev two waits for business hours. Sev three
just gets logged — nobody's woken up for it.

## S5 · OUTRO CARD

The fix for fatigue is precision, not more alerts. Next up: cost
management and optimization — knowing what a pipeline actually
costs.
