# Course Wrap-Up: Choosing Where to Specialize Next

Eighteen chapters ago, this course opened by asking what happens when the job includes Oracle,
MySQL, or PostgreSQL, not just SQL Server. Six lessons ago, that question stopped being
hypothetical — you became Harborline Retail Group's cross-platform DBA, stood up `ora-fin01`,
`mysql-web01`, and `pg-analytics01`, secured and backed up all three, fixed a real slow-performance
problem on each, and turned it into interview answers. That's the course. This lesson closes it out
and points you at what's genuinely next.

## What you'll learn

- What this course actually built, chapter by chapter, and how the Harborline project pulled it together
- Where this course sits in the SQL Server Database Administrator path — and where it doesn't end the path
- What NoSQL, Document & Graph Databases covers, and why it's the path's real closing course
- How to decide where to specialize once every course in the path is behind you

## What this course built

Chapters 1 covered the mindset shift: some DBA instincts transfer across platforms, syntax and
architecture detail don't. Chapters 2 through 16 then went deep on Oracle, MySQL, and PostgreSQL in
turn — architecture and installation, security and user management, backup and recovery,
performance tuning, and replication and high availability, five chapters per platform. Chapter 17
turned that into cross-platform migration skill: assessing a migration project and handling the
real differences moving SQL Server logic and data to each of the other three. Chapter 18, this
chapter, put all of it to work in one continuous scenario at Harborline.

## Where this course sits in the path

This course closes out the "Multi-Platform Databases" stage's first course — but not the stage
itself, and not the path. The SQL Server Database Administrator path's final stage pairs this
course with **NoSQL, Document & Graph Databases**, and that second course is the one that actually
closes the path. This course deliberately covers the relational side of "the platforms every senior
DBA eventually runs into" — Oracle, MySQL, PostgreSQL. The other half of that same real-world
picture is non-relational: MongoDB, Azure Cosmos DB, and Neo4j, covering document stores, globally
distributed databases, and graph databases — data models where relational thinking genuinely
doesn't apply, which is exactly why it's a separate course rather than a chapter tacked onto this
one.

## What's next: NoSQL, Document & Graph Databases

That course applies the same discipline this one did — real architecture, real security, real
querying, on real platforms — to MongoDB's document model, Cosmos DB's globally distributed
multi-model design, and Neo4j's graph model. If Harborline's next data problem were something like
a recommendation engine (a graph problem) or a flexible product catalog with wildly inconsistent
fields across categories (a document problem), that's the toolkit the next course builds. It's the
last course in this path, and finishing it is what completes the entire SQL Server Database
Administrator path — Job Ready, Advanced SQL Server, and Multi-Platform Databases, all the way
through.

## Choosing where to specialize next

You don't need to master every platform in this course and the next one equally. The path's own
framing is a checkpoint, not a finish line for any one platform: DP-300 sits partway through, and
this course explicitly said "credible exposure," not deep specialization, is the goal here. Once
the path is complete, the honest next step is picking one platform — maybe the one closest to
what Harborline (or your actual employer) runs the most of — and going deeper than any single
course in a generalist path can take you. That's a deliberate choice to make later, with real job
requirements in front of you, not a decision this lesson makes for you.

## Key terms

| Term | Meaning |
|---|---|
| Multi-Platform Databases stage | The path's final stage, containing this course and NoSQL, Document & Graph Databases |
| Document database | A NoSQL database storing flexible, semi-structured records (e.g., MongoDB) |
| Graph database | A database modeling data as nodes and relationships (e.g., Neo4j) |
| Specialization | Going deeper into one platform after broad, credible exposure across many |
