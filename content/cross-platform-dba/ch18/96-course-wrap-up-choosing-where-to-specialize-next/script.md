# Script — Course Wrap-Up: Choosing Where to Specialize Next

## Segment 1 (title)

Eighteen chapters ago, this course asked what happens when the job includes Oracle, MySQL, or PostgreSQL, not just SQL Server. Six lessons ago, that stopped being hypothetical — you became Harborline Retail Group's cross-platform DBA. This lesson closes the course out.

## Segment 2 (steps: what this course built)

Chapter 1 covered the mindset shift. Chapters 2 through 16 went deep on Oracle, MySQL, and PostgreSQL in turn — architecture, security, backup, performance, and replication, five chapters per platform. Chapter 17 turned that into cross-platform migration skill. Chapter 18 put it all to work at Harborline.

## Segment 3 (steps: where this course sits in the path)

But this course doesn't close the path. The Multi-Platform Databases stage pairs this course with NoSQL, Document & Graph Databases. This course covered the relational half — Oracle, MySQL, PostgreSQL. The next course covers the non-relational half — MongoDB, Cosmos DB, and Neo4j — and it's the course that actually finishes the path.

## Segment 4 (code: deciding where to specialize)

This path was always about credible exposure, not deep specialization in any one platform — DP-300 was a checkpoint partway through, not the end. Once the path is fully complete, the real next step is picking one platform close to your actual job and going deeper than any generalist path can take you.

## Segment 5 (outro — course complete)

This course is done. One course remains in the SQL Server Database Administrator path: NoSQL, Document & Graph Databases, covering MongoDB, Cosmos DB, and Neo4j — the course that closes out the entire path.
