# Script — Portfolio Presentation Strategy

## Segment 1 (title)

Lesson 16 got this project onto your resume as a few tight bullets. A portfolio is where you back those bullets up. This lesson is about packaging this project so it proves those claims in under two minutes.

## Segment 2 (steps: what belongs in the repo)

Commit the real artifacts — the SSIS package and the T-SQL DDL are readable directly on GitHub, so a reviewer can open your actual ETL logic without installing anything. Since SSRS and Power BI files aren't viewable in a browser, screenshots stand in for them. A README ties every piece together.

## Segment 3 (code: README structure)

Write the README in this order: the business problem first, then the architecture, then the design decisions worth explaining, then the screenshots. That order does the work of connecting the pieces for the reviewer, instead of leaving them to guess.

## Segment 4 (steps: business problem first)

The most common mistake in a portfolio review is opening with the tool list. Open with the problem instead: what a production manager couldn't see before. Then the approach, the proof — the report and dashboard — and one real tradeoff you can explain.
