# Script — Account Hierarchies and Trees

## Segment 1 (title)

A flat list of cost centers is enough to record transactions, but not enough to report the way a business thinks about itself — all of Manufacturing, all of North America. That rollup capability comes from trees.

## Segment 2 (code)

A tree is a hierarchical structure built from a value set's values, organizing them into parent-child relationships. A cost center tree groups individual cost centers under regional or divisional parents, which roll up to an enterprise-wide total.

## Segment 3 (steps)

A summary value becomes a parent node; detail values beneath it become children. Transactions post only to detail values. Parent values let a report say "show me all of Manufacturing" without anyone listing every child by hand.

## Segment 4 (steps)

A single tree can have multiple tree versions, each with its own effective date range, because org hierarchies change. A report can run against a specific version — last year's numbers through last year's hierarchy, this year's through this year's.

## Segment 5 (outro)

Hierarchies also reduce maintenance elsewhere — cross-validation rules can reference a hierarchy instead of listing every value, and allocations can target a parent node automatically. Next up, lesson twenty-four: cross-validation rules.
