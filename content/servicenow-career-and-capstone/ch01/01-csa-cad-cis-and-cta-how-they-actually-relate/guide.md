# Lesson 1 — CSA, CAD, CIS & CTA: How They Actually Relate

- How CAD and CIS branch from CSA toward different kinds of work

## The four letters, defined

Across courses 1 through 13 of this path you built real skills — system
administration, scripting, ITSM implementation, CMDB and Discovery,
integrations, security, DevOps, performance tuning, and architecture. Four
ServiceNow credentials map onto that same territory, and it's worth being
precise about what each one actually certifies before you plan which to
pursue:

- **CSA — Certified System Administrator.** The foundational credential.
  It certifies baseline competence across the platform itself: navigation,
  users and groups, tables and fields, basic workflow and UI configuration,
  core ITSM processes. This is what Courses 2 and 3 of this path (Platform
  Fundamentals and System Administration) built toward.
- **CAD — Certified Application Developer.** Certifies the ability to
  build custom applications on the platform — scripting, Flow Designer,
  application scoping, data design for net-new apps. This maps to Courses
  4 through 7 (Flow Designer, JavaScript, Scripting & Application
  Development, IntegrationHub).
- **CIS — Certified Implementation Specialist.** Not one credential but a
  family of them, each tied to a specific product module: CIS-ITSM,
  CIS-CSM, CIS-HR, CIS-Discovery, and others. Each certifies the ability to
  configure and implement that specific module for a real organization.
- **CTA — Certified Technical Architect.** The advanced credential this
  whole path builds toward with Course 13 (Technical Architecture) and this
  course's capstone. It certifies the ability to make and defend
  architectural decisions across a ServiceNow program — not just configure
  one module, but design how an entire implementation holds together.

## CSA is the floor, not a destination

Every CIS specialization lists CSA as a formal prerequisite. That's not
a technicality — it reflects a real dependency. You cannot reasonably
implement CIS-ITSM's incident and problem workflows if you don't already
know how tables, roles, and basic configuration work at the CSA level.
CAD doesn't list CSA as a hard prerequisite in the same way, but in
practice the same logic applies: you can't develop an application
sensibly on a platform you don't yet understand as an administrator.

The practical implication: if you're planning a certification path at
all, CSA goes first, regardless of which direction you head afterward.
It's the one credential almost everyone in a ServiceNow career ends up
holding, because it's the floor the rest of the ladder stands on.

## From CSA, two branches: CAD and CIS

Past CSA, the ladder forks based on the kind of work you're aiming at,
not based on which one is "better":

- If the work you want is **building new functionality** — custom
  applications, scripted business logic, integrations — CAD is the
  credential that matches it.
- If the work you want is **implementing a specific module for a
  business** — configuring CIS-ITSM's incident/problem/change processes,
  or CIS-Discovery's CMDB population rules, for a client or employer —
  the relevant CIS specialization matches it.

Nothing stops you from holding both a CAD and a CIS credential, and
plenty of working consultants do, because real implementations often
need both configuration and custom development. But as a sequencing
matter, pick the branch that matches the work you actually did with
depth in Courses 1–13, not the branch you haven't touched yet. Lesson 2
goes deeper on choosing a specific CIS specialization.

## CTA sits apart — and later

This is the point most new ServiceNow professionals get wrong: CTA is
**not** simply "the next certification after CAD or CIS." ServiceNow
gates CTA behind real, demonstrated implementation experience — the
kind that only accumulates across multiple real projects, working with
real stakeholders, making real tradeoffs under real constraints. A CTA
candidate is expected to defend architectural decisions the way this
course's capstone (Chapters 4–6) has you practice: presenting a design,
justifying it under questioning, revising it based on real feedback.

That's why CTA isn't a short-term goal for someone finishing this path
today. It's a credential to work toward over years of real project
experience, after CSA and a CAD or CIS specialization are already in
hand. Treat it as the top of the ladder you're aware of and climbing
toward — not a box to check this quarter.

## Key terms

| Term | Meaning |
|---|---|
| CSA | Certified System Administrator — the foundational, prerequisite credential |
| CAD | Certified Application Developer — certifies building custom applications |
| CIS | Certified Implementation Specialist — a family of module-specific credentials (CIS-ITSM, CIS-CSM, CIS-HR, CIS-Discovery, etc.) |
| CTA | Certified Technical Architect — the advanced, experience-gated architecture credential |
