# Lesson 10 — Choosing a Model for a Task · Voiceover script

Segments map 1:1 to slides. Target: ~2.5 minutes total.

---

## S1 · TITLE CARD

Five providers, four-ish tiers each, open-weight or closed — that's a lot of options. This lesson
is the actual process for picking one, straight from how a provider itself tells you to decide.

## S2 · STEPS CARD (capabilities / speed / cost / effort)

Four questions, before anything else. What capabilities does this task actually need — long
context, tool use, vision? How fast does it need to respond — real-time chat versus an overnight
batch job are completely different? What's the real budget at production volume, not demo volume?
And can you tune effort within one model before switching models entirely — that's often a better
first lever than jumping tiers.

## S3 · STEPS CARD (efficiency-first vs capability-first, as a process)

Pick one of two strategies, then actually test it. Efficiency-first: start cheap and fast, test
against real examples, upgrade only where you find a genuine capability gap. Capability-first:
start with the strongest model for a genuinely hard task, then look for room to step down once
you understand what it actually needs. Neither one means always reaching for the biggest model.

## S4 · CODE CARD (worked example: three tasks, three tiers)

Three real tasks. A high-volume FAQ chatbot — efficiency-first, fastest tier. Drafting a
first-pass document from a messy transcript — moderate complexity, a balanced mid-tier model. A
multi-step coding agent refactoring an unfamiliar codebase — capability-first, the flagship tier,
with room to downgrade only once the workflow is proven out.

## S5 · OUTRO CARD

Capabilities, speed, cost, effort — then test against your real data, not a marketing benchmark.
Next lesson: what that actually costs, with real numbers across the full cost-latency-quality
trade-off.
