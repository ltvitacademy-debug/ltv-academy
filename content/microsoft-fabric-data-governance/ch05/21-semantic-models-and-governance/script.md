# Lesson 21 — Semantic Models and Governance · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

---

## S1 · TITLE CARD

A semantic model isn't just relationships and measures — it's a
governed Fabric item in its own right, with an owner, a label, and
a permissions tab of its own.

## S2 · SCREENSHOT CARD (item overview tab)

This is a real semantic model's Overview tab — owner, sensitivity
label, refresh time, and every table and column already documented,
right there before anyone builds a single report against it.

## S3 · SCREENSHOT CARD (manage permissions)

Manage permissions is where the owner grants three real levels:
Read, to view content built from the model; Build, to create new
reports directly against it; and Reshare, to pass Read access to
someone else. This is a separate, deliberate grant — not the same
thing as a workspace role.

## S4 · SCREENSHOT CARD (request access dialog)

When someone without Build access wants in, they hit Request
access — and the owner has already decided what that looks like:
an email straight to them, or written instructions pointing at the
real process, like a security group to join.

## S5 · OUTRO CARD

Governance that travels with the model itself, not bolted on
after. Next lesson: governed self-service analytics — how
Promoted, Certified, and Master Data badges do the same job at
scale, across an entire catalog of items.
