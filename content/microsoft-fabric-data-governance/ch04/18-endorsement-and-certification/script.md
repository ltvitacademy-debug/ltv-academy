# Lesson 18 — Endorsement and Certification · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

## S1 · TITLE

Once you can find an item, the next question is whether you should trust it. That's what endorsement answers.

## S2 · STEPS — Promoted vs. Certified

Fabric has two endorsement levels. Promoted is self-service — anyone with write access to an item can apply it themselves, no review needed. Certified is stronger — restricted to a security group a tenant admin has specifically authorized. Both exist to steer people toward content that's already worth trusting.

## S3 · SCREENSHOT — The Endorsement tab

Endorsement lives in an item's own settings, under the Endorsement tab — the same four options, None, Promoted, Certified, and Master Data, no matter what kind of item you're looking at.

## S4 · SCREENSHOT — Promoting content

Selecting Promoted and clicking Apply is open to anyone with write access. It's a lightweight "I vouch for this" signal, not a formal review.

## S5 · SCREENSHOT — Certifying content

Certified uses the exact same dialog, but the option is grayed out unless you're in an authorized security group. Everyone else gets a link explaining how to request certification instead.

## S6 · SCREENSHOT — The admin Certification setting

A Fabric admin turns certification on from Tenant settings, under Certification — naming the specific security groups allowed to certify, optionally linking the org's own review-process documentation, and choosing whether domain admins can override it.

## S7 · SCREENSHOT — Where the badge shows up

Once applied, the badge travels with the item: in search results, in the OneLake catalog, and in an Endorsement column on Browse lists — exactly where a student is deciding which item to actually use.

## S8 · STEPS — Why it matters

This is a cheap governance win. A visible badge stops five people from quietly rebuilding the same report, because the trustworthy one is obvious the moment they're searching for it.

## S9 · OUTRO

Trusting an item is step one. Next lesson: lineage — tracing exactly where that item's data came from.
