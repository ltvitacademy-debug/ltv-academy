# Script — Profiles & Permission Sets

## Segment 1 (title)

Licenses set the ceiling, roles decide which records a user sees. This lesson covers what decides what a user can actually do — through Profiles and Permission Sets.

## Segment 2 (steps: Profile)

Every user has exactly one Profile — mandatory, not additive with any other profile. It's the baseline: which objects are visible at all, what actions are allowed, and default field-level security. Typical profiles look like Sales User or System Administrator, one per broad job function.

## Segment 3 (steps: Permission Sets)

Permission Sets grant additional permissions on top of the Profile. A user can have zero, one, or several stacked together, and they only ever add — never remove. They're the right tool for exceptions: a handful of users needing one extra piece of access without a whole new profile.

## Segment 4 (outro)

A user's real access is their Profile plus every Permission Set assigned to them, unioned together. Next up: Sharing Rules — extending record visibility beyond what the role hierarchy grants by default.
