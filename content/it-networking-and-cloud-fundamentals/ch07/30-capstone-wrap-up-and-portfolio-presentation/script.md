# Script — Capstone: Wrap-Up & Portfolio Presentation

## Segment 1 (title)

The network is built, the fault is found, and the fix works. What's left is the part that actually matters for a job search: turning this project into something a hiring manager can look at and understand without having lived through the last three lessons.

## Segment 2 (steps)

A strong portfolio entry isn't a transcript of everything you did — it's a focused document a stranger can read in a few minutes. At minimum, it needs an architecture diagram showing the subnet, the firewall, the VPN tunnel, and the cloud systems it connects to; a README explaining the brief and the design decisions; the problem and fix, stated plainly; and a way to verify the fix — the actual test that proves it worked, not just a claim that it did.

## Segment 3 (code)

The problem/fix narrative is the part that actually demonstrates skill. A good version reads like this: employees could reach file shares but not the cloud inventory system, even with the VPN tunnel confirmed up. Isolating the problem in stages — the tunnel, then the destination — found that the outbound firewall rule had never been updated for the new system. Adding that rule resolved it. That's four sentences, and it shows the methodology in action far more convincingly than just saying "I fixed a network issue." The same shape works out loud too: state the symptom, state what got ruled out and why, state the fix — and resist narrating every dead end along the way.

## Segment 4 (outro)

That closes out IT, Networking & Cloud Fundamentals — hardware, networking, core protocols, security services, troubleshooting, the cloud, and now a capstone that pulled all of it together. Next in the DevOps Engineer path is Linux Administration, moving from the network layer onto the operating system itself: the CLI, permissions, users, processes, and the Bash scripting that automates all of it.
