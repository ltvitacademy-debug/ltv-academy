## The problem: routine journals shouldn't need a human click

By Lesson 10, posting was something you (or a controller) chose to do. For high-volume, trusted, routine journals — recurring accruals that are the same every month, allocations generated by a rule you already reviewed — requiring a person to manually post every single batch adds friction without adding safety. **AutoPost criteria sets** let General Ledger post matching batches automatically, on a schedule, without a manual click.

## What a criteria set matches on

An AutoPost criteria set is defined by combining:

- **Journal source** — for example, Allocation or Payables
- **Journal category** — for example, Allocation or Standard
- **Balance type** — actual, budget, or encumbrance
- **Period** — a specific period or range of effective dates

You can define **multiple criteria sets**, each targeting a different combination, and assign each one a **priority** so General Ledger knows which to evaluate first when more than one could apply to the same batch.

```
Criteria Set 1 (priority 1): Source = Allocation, Category = Allocation, Balance Type = Actual
Criteria Set 2 (priority 2): Source = Payables,   Category = Standard,  Balance Type = Actual
```

A batch from Solara Fixtures' monthly allocation run matches Criteria Set 1 and posts automatically the moment the allocation process completes and validates cleanly — no one has to open Manage Journals and click Post.

## Why this isn't right for every journal

AutoPost is a good fit exactly because the journals it targets are **predictable and already trusted** — the same accrual every month, an allocation whose rule was reviewed when it was built. It is a poor fit for one-off manual adjustments, correcting entries, or anything a controller specifically wants to eyeball before it changes a balance. Scoping criteria sets tightly by source and category (as Lesson 7 set up) is what keeps AutoPost from accidentally posting something that actually needed a second look.

## Key terms

| Term | Meaning |
|---|---|
| AutoPost criteria set | A defined combination of source, category, balance type, and period that posts matching batches automatically |
| Priority | Determines which criteria set is evaluated first when more than one could match |
