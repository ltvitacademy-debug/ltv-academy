## What synthetic data is

Synthetic data is data that's artificially generated — often by another model — to stand in for real data, rather than being collected directly from real people or real events. Organizations reach for it for reasonable reasons: it can fill gaps where real examples of some rare but important case are scarce, it can augment a small dataset to give a model more examples to learn from, and it's sometimes used specifically because it doesn't contain any single real person's actual information.

## Why it doesn't automatically solve the earlier problems

It's tempting to treat synthetic data as a clean escape from provenance, consent, quality, and bias concerns — after all, if it's not real data, who's it harming? In practice, none of those concerns disappear:

- **It still encodes the patterns of whatever real data it was modeled on.** Synthetic data is typically generated by a model that itself learned from real examples. If that underlying data had a bias (Lesson 9), the synthetic data generated from it can reproduce and sometimes amplify that same bias, just with no single real example you can point to.
- **It doesn't automatically protect privacy.** A synthetic record that's generated by closely mimicking individual real records can still leak identifiable details of the people in the original data, especially if the generator was trained on a small or distinctive dataset. "Synthetic" is not a synonym for "anonymous" — that has to be verified, not assumed.
- **Quality still applies.** The quality dimensions from Lesson 8 don't go away because the data is generated rather than collected. Synthetic data can still be inconsistent, unrepresentative, or simply low quality if the generation process was.

## What synthetic data raises that real data doesn't

The one governance question that's genuinely new here is documentation honesty: a model trained partly or fully on synthetic data needs that fact recorded clearly, not blended invisibly into "the training data" as if it were all collected the same way. Downstream, anyone evaluating the model's behavior needs to know which parts of its training experience were real-world observation and which were generated — because the two carry different kinds of risk, and a model card or governance review (Lesson 12 covers model documentation) that doesn't distinguish them is giving an incomplete picture.

## The honest framing

Synthetic data is a legitimate tool, not a shortcut around governance. It still needs provenance (what real data, or what generation process, produced it), a bias check against what it was modeled on, and the same quality bar as any other training data — plus one more disclosure real data doesn't require: a clear, documented statement that it's synthetic in the first place.

## Key terms

| Term | Meaning |
|---|---|
| Synthetic data | Artificially generated data used to stand in for real data in training |
| Data augmentation | Using synthetic or generated examples to give a model more data to learn from |
| Anonymity (not assumed) | The property that no individual can be re-identified — something that must be verified for synthetic data, not assumed by default |
