# Script — Invoice Import Overview

## Segment 1 (title)

Every invoice so far has been entered one at a time by a person. That's fine for a handful a day. It falls apart the moment hundreds arrive through EDI, a spreadsheet upload, a scanning tool, or a supplier portal. This lesson covers how Payables absorbs invoices in bulk, through import.

## Segment 2 (steps)

Imported data doesn't become a real invoice instantly - it lands in open interface tables first, a staging area. Whatever generated the data, a loader, a feed, a scanning tool, writes rows there, not directly into Payables' own invoice tables.

## Segment 3 (steps)

The Import Payables Invoices process reads those staged rows and builds real invoices and lines from them - the same kind of invoice you've built manually all chapter, just generated by a batch process. It's a scheduled step, not something that fires automatically the instant data lands.

## Segment 4 (steps)

Not every staged row survives. Rows get rejected when no valid supplier site can be identified, when the invoice number duplicates one already entered for that supplier, or when the source value isn't a valid predefined option. Depending on setup, supplying payment terms directly when the source doesn't allow it can reject a row too.

## Segment 5 (outro)

Every import run produces a rejections report alongside whatever it successfully created. A batch that creates 395 out of 400 isn't actually done until someone checks why the other five failed and fixes the underlying data - otherwise those five supplier invoices just vanish from view.
