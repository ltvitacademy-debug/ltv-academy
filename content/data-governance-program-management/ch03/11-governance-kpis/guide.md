# Lesson 11 — Governance KPIs

**Chapter 3 · Measuring Governance · Lesson 11 of 25**

## What you'll learn

- What separates a governance KPI from just any number you could track
- The four categories most governance programs end up measuring: program health, data quality, adoption, and issue resolution
- The difference between leading and lagging indicators, and why a program needs both
- How to spot a vanity metric before you build a dashboard around it

## Why governance needs KPIs at all

A governance program that can't point to a number is a program that can't defend its own budget. Chapters 1 and 2 covered how to launch a program and write its policies — this chapter is about proving, with evidence, that any of it actually worked. A **KPI** (key performance indicator) in a governance context is a metric that is tied to a specific decision someone will make, has a named owner who is accountable for moving it, and is tracked consistently over time rather than pulled together once for a slide.

That last part matters more than it sounds. A number computed once for a steering committee meeting is a data point. The same number computed the same way every month, with a trend line behind it, is a KPI. Lesson 13 covers the dashboards that make that trend visible; this lesson is about choosing the right numbers in the first place.

## The four categories governance programs track

Most governance KPI sets cluster into four groups:

1. **Program health** — is the governance operating model itself functioning? Example: percentage of data domains with an assigned owner, number of open council decisions past their target date.
2. **Data quality** — is the data actually getting better because of governance activity? Example: pass rate on critical data quality rules, trend in duplicate records for a governed domain.
3. **Adoption** — are people actually using what governance built? Example: percentage of new reports built against approved, governed data sources rather than ungoverned spreadsheets. Lesson 12 goes deeper on this category specifically.
4. **Issue resolution** — is the escalation path from Lesson 9 actually working? Example: average time from an issue being logged to it being resolved, number of issues reopened after "resolution."

A mature program tracks at least one KPI from each category. A program that only tracks data quality numbers, for instance, can look successful on a dashboard while nobody outside the data team has adopted a single governed process.

## Leading indicators vs. lagging indicators

Every KPI set needs both kinds of signal:

- A **lagging indicator** confirms an outcome after it happened — last quarter's data quality pass rate, the count of policy violations closed last month. It tells you what already happened.
- A **leading indicator** predicts a problem before it shows up in the lagging numbers — the count of data domains still missing an assigned steward, the number of new data sources onboarded without going through the governance intake process. It tells you where trouble is heading.

Programs that only report lagging indicators are always explaining the past. A leading indicator like "domains without an assigned owner" gives a council something to act on *before* that domain shows up in next quarter's quality report with a bad pass rate.

## Avoiding vanity metrics

A vanity metric looks good in a steering committee deck and drives no decision. "Number of policies published" is a classic example — it goes up every time someone writes a policy document, regardless of whether anyone follows it. The test for any candidate KPI is simple: if this number moved sharply in either direction, would anyone in the room change what they do next? If the honest answer is no, it's a vanity metric, not a KPI, and it doesn't belong on the scorecard Lesson 13 builds.

## Key terms

| Term | Meaning |
|---|---|
| KPI | A metric tied to a decision, with a named owner, tracked consistently over time |
| Leading indicator | A metric that predicts a future problem before it shows up in outcomes |
| Lagging indicator | A metric that confirms an outcome after it has already happened |
| Vanity metric | A number that looks good but doesn't change anyone's next action |
