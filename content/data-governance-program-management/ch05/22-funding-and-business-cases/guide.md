# Lesson 22 — Funding and Business Cases

**Chapter 5 · Sustaining Governance · Lesson 22 of 25**

## What you'll learn

- Why the business case that launches a program is not the business
  case that keeps it funded
- How to move governance from a one-time project budget to a standing
  operating line item
- What a value realization report has to show to defend a budget,
  and what it doesn't need
- How to respond when a budget cut or a departed champion threatens
  the program's funding

## The first business case already did its job

Data Governance Foundations' Chapter 5 covered the one-page business
case that gets a *pilot* funded: a problem in business terms, a scoped
ask, named resources, and a way to measure anticipated value. That
document's whole purpose is to win a first yes. Once the pilot proves
itself and the program scales (the roadmap from Lesson 21), that
one-time ask is gone. Something else has to keep the money flowing
every single budget cycle after that.

## From project budget to run-rate budget

Many governance programs start as a funded *project* — a line item
with a start date, an end date, and a champion who personally pushed it
through. That funding model works for a pilot. It does not survive
contact with year two unless the program converts to a **run-rate
budget**: an ongoing operating line, owned by a cost center, renewed
the same way payroll or software licensing is renewed, not re-pitched
from scratch every twelve months.

Making that conversion requires the same credibility a first business
case needed, pointed in a different direction — not "fund this new
thing" but "this is now how we operate, and stopping it would cost
more than continuing it."

## What a value realization report has to show

A sustaining program defends its run-rate budget with a **value
realization report** — evidence that the anticipated value from the
original business case actually happened, built from the same KPIs
and dashboards covered in Chapter 3 of this course:

- **Value delivered against the original ask.** If the pilot's
  business case promised fewer reconciliation hours or fewer
  compliance findings, the report shows the actual numbers, not a
  repeat of the original promise.
- **Cost of the program versus cost of not having it.** What
  incidents, fines, or rework did the program prevent or shorten —
  framed, like Foundations' Lesson 26 taught, in terms the specific
  audience (CFO, CIO, business unit leader) already weighs.
- **What's different this cycle.** New domains covered, new KPIs
  trending the right direction, new risk the program is now catching
  that it wasn't catching last year.

This report doesn't need to promise anything new to justify the
*existing* budget — proving the existing ask already paid off is the
argument. New asks (an expansion, new tooling) get their own scoped
case, same discipline as the original pilot pitch.

## When the budget gets cut anyway

Budgets get cut for reasons that have nothing to do with how well the
program is running — a bad quarter, a company-wide freeze, a
reorganization. When that happens, the roadmap's now/next/later
structure from Lesson 21 is what makes the conversation survivable:
the program can say precisely which committed "Now" work stays,
which "Next" work slips, and which "Later" work simply waits, instead
of the whole program collapsing because there was no way to cut less
than everything.

## When the champion leaves

A program whose funding depended entirely on one sponsor's personal
relationships is fragile the moment that sponsor changes roles or
leaves. The fix isn't found during the crisis — it's the Chapter 4
discipline of spreading sponsorship and communication across the
council and multiple stakeholders *before* it's tested, so the value
realization report, not one person's memory of why this mattered,
carries the renewal conversation.

## Key terms

| Term | Meaning |
|---|---|
| Run-rate budget | An ongoing operating budget line for governance, renewed like any standing cost center rather than re-pitched as a new project each cycle |
| Value realization report | Evidence, built from existing KPIs, that a program's originally promised value actually materialized |
| Budget defense | The renewal-cycle conversation where a sustaining program justifies its existing budget using delivered value, not a fresh pitch |

## Lab

Using the KPIs or metrics you'd track for a governance program (your
own organization's, or a representative one), draft a one-page value
realization report with three sections: value delivered against an
original promise (one concrete before/after number), cost of not
having the program (one plausible scenario it prevented or shortened),
and what's different this cycle (one new thing the program now
covers). Then write two sentences on what you'd protect first if the
budget were cut by a third.
