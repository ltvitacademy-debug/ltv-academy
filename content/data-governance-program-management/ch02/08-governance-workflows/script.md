# Lesson 8 — Governance Workflows · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

## S1 · TITLE

A procedure tells one person the steps for one task. A workflow is the bigger picture — the full
path a request takes across different people until it's actually resolved.

## S2 · STEPS — The shared stages

Almost every governance workflow shares the same backbone: intake, where the request enters;
triage, sorting what it is and how urgent; routing, getting it to the right person using the RACI
matrix; resolution, the actual fix; verification, confirming it actually worked; and closure,
recording what happened.

## S3 · STEPS — Three common workflows

An access request routes to the data owner for approval and IT provisions it. A data quality issue
gets triaged by severity and routed to a steward for a fix. A policy exception request needs a
business reason, a time-bound scope, committee approval, and an expiration date so it doesn't
quietly become permanent.

## S4 · STEPS — Tool versus design

Many programs run these through a ticketing system or a data catalog's workflow feature, or even a
spreadsheet for a small program. But the tool is just delivery — a well-configured tool running an
undefined process just produces fast, untracked chaos. Design the stages and the accountability
first.
