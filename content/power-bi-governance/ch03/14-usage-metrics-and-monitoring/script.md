# Lesson 14 — Usage Metrics and Monitoring · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

---

## S1 · TITLE CARD

Endorsement and lineage are about what a dataset claims to be. Usage metrics checks whether that claim actually holds up — starting with turning it on.

## S2 · SCREENSHOT (toggle on)

A report owner switches usage metrics on from the report's own menu, and Power BI generates a real report in the background, ready to view like anything else in the workspace.

## S3 · SCREENSHOT (usage metrics report)

It breaks down views per day, unique viewers, and — most important for governance — a Views by user table naming exactly who's actually looking. That's the difference between assuming people use it and knowing specifically who does.

## S4 · SCREENSHOT (finding the report)

It's not off in a separate corner either — View usage metrics report sits in the same menu as lineage, right alongside every other item action.

## S5 · STEPS CARD (what it tells governance)

Steady views confirm a certified item is actually adopted. Zero views on something certified is a red flag — either it's obsolete, or people quietly moved to something uncertified, which is worse. And views-by-user ties usage to real, named people.

## S6 · SCREENSHOT (monitoring hub)

Usage metrics covers one report. For the whole tenant, the monitoring hub tracks every job run — refreshes, dataflows, pipeline deployments — so a failed refresh shows up here before a user ever notices stale data.

## S7 · OUTRO CARD

Next lesson: auditing Power BI activity. Usage tells you what's viewed — auditing tells you exactly who did what, down to the individual action.
