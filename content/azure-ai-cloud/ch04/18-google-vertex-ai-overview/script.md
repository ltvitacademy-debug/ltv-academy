# Script — Google Vertex AI, Overview

## Segment 1 (title)

Two clouds down, one more to go — Google's answer to the same problem Azure AI Foundry and AWS Bedrock both solve: giving a developer one place to find, deploy, and call a foundation model.

## Segment 2 (screenshot: model garden search)

Model Garden is that one place — Google's own Gemini and Gemma models sit alongside partner models and open-weight models like Llama and Mistral, all searchable from one catalog instead of a vendor-by-vendor hunt across separate documentation sites.

## Segment 3 (screenshot: deploy options dropdown)

Pick a model and its own page offers Deploy options — fine-tune it, open it in a notebook, view its code, or deploy it with one click. That one-click path specifically targets Vertex AI, the managed endpoint service underneath Model Garden that actually serves the model once it's deployed, the same way Azure AI Foundry sits underneath a model deployed from its own catalog.

## Segment 4 (screenshot: deploy on vertex ai pane)

One click still opens a real configuration pane — region, machine spec, GPU type — the same category of decision Lesson 12 walked through for Azure's own GPU VM families, just under Google's own naming for the equivalent choices.

## Segment 5 (code: naming note)

One naming note worth knowing: Google's own documentation rebranded this whole product area to Gemini Enterprise Agent Platform in 2026. The console, the SDK, and the deployment pane you actually click through still say Vertex AI — which is also the name this lesson, and most working engineers, still use day to day.

## Segment 6 (outro)

A real third option, with its own catalog and its own name for the same underlying idea. Next up: actually deciding between the three.
