# Lesson 34 — The Long Path to Data Governance Architect · Voiceover script

Segments map 1:1 to slides. Target: ~2-3 minutes total.

## S1 · TITLE

This lesson describes a realistic, multi-year career ladder from entry-level governance work up to data governance architect — a general shape to expect, not a guaranteed timeline for any individual career.

## S2 · STEPS (the ladder)

Analyst or Steward executes defined tasks. Senior Analyst owns a full domain and handles ambiguous requests. Governance Manager runs the program itself — stakeholders, roadmaps, budget. Architect designs how governance works at an enterprise, cross-platform level.

## S3 · STEPS (what actually changes)

Analyst to Senior Analyst is deciding how to handle a task nobody wrote instructions for. Senior Analyst to Manager is owning whether the whole program is funded and trusted. Manager to Architect is designing systems across platforms, not running the org chart.

## S4 · CODE (why architect takes longer)

The architect rung needs both deep governance judgment and hands-on technical breadth across the platforms this path covered — Purview, Fabric, Databricks Unity Catalog, Snowflake, Power BI governance, Azure and AWS — which is why it sits at the top and takes sustained, multi-year experience.
