# Script — What Is Analytics Engineering?

## Segment 1 (title)

A data engineer gets data into the warehouse. A data analyst pulls data out. Analytics engineering is the layer in between — transforming raw, loaded data into clean, tested, documented models that analysts and BI tools can trust, without everyone re-deriving the same logic themselves.

## Segment 2 (screenshot: dbt Cloud IDE)

Everything in dbt lives in a project developed inside a real IDE with a visual map of how everything connects. That lineage graph isn't a diagram someone drew — it's generated directly from ref calls in the SQL itself, always accurate, never stale.

## Segment 3 (steps: what dbt adds)

In one sentence: dbt turns SQL transformation logic into version-controlled, tested, documented, and automatically ordered models, run directly against your warehouse. Four things it adds: dependency management through ref, testing, documentation, and version control plus CI/CD.

## Segment 4 (steps: what this course assumes)

This course assumes real SQL fluency and cloud warehouse basics from Snowflake, immediately before this one in the Analytics Engineer path. Nothing here re-teaches SQL — every lesson is about the modeling layer dbt builds on top of a warehouse you already know.
